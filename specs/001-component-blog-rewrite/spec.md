# Feature Specification: 정적 HTML 블로그 컴포넌트 재구현

**Feature Branch**: `001-component-blog-rewrite`

**Created**: 2026-07-17

**Status**: Draft

**Input**: User description: "현재 core/ 아래 정적 HTML로 존재하는 블로그 화면(홈, 아티클 상세 — 각각 dark/light 테마)을 재구현한다. 사용자가 보는 화면과 동작은 기존과 완전히 동일하게 유지되어야 한다. 헤더/네비게이션/카드/테마 토글처럼 여러 화면에서 반복되는 UI 요소는 한 곳에서 관리되어, 하나를 고치면 모든 화면에 일관되게 반영되어야 한다. 홈 화면과 아티클 상세 화면은 각각 독립적으로 완성/검증 가능해야 하며, dark/light 테마 전환 시 레이아웃과 콘텐츠는 동일하게 유지되어야 한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 — 홈 화면 열람 (Priority: P1)

블로그 방문자가 홈 화면에 진입하면, 히어로 캐러셀과 블로그 카드 그리드가 포함된 메인 페이지를 볼 수 있다. 현재 `core/home-dark.html` / `core/home-light.html`에서 보이는 것과 시각적·기능적으로 완전히 동일한 화면이어야 한다.

**Why this priority**: 홈 화면은 블로그의 첫인상이자 가장 높은 트래픽을 받는 진입점이다. 여기가 정상이어야 사용자가 글로 유입된다.

**Independent Test**: 홈 화면만 단독 빌드하여 브라우저에서 열고, 기존 HTML 화면과 동일한 레이아웃·색상·인터랙션이 재현되는지 시각적으로 비교할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 홈 URL에 접속, **When** 페이지가 로드되면, **Then** 고정 네비게이션 바(Revi 로고, Home/About/Feeds/Bookmark 링크, LOGIN 버튼)가 상단에 표시된다
2. **Given** 홈 화면이 로드됨, **When** 히어로 섹션을 보면, **Then** 3장의 슬라이드를 가진 캐러셀이 8초 간격 자동 재생되며, 이전/다음 버튼과 인디케이터 도트가 표시된다
3. **Given** 홈 화면이 로드됨, **When** 캐러셀 아래를 스크롤하면, **Then** "Entry Stream" 섹션 헤더(왼쪽 녹색 보더, 메타 정보)와 3열 반응형 블로그 카드 그리드가 표시된다
4. **Given** 블로그 카드 위에 마우스를 올리면, **When** 호버 상태가 되면, **Then** 썸네일 이미지가 확대(scale)되고 제목 색상이 변경되며 화살표 아이콘이 우측으로 이동한다
5. **Given** 카드 그리드 아래를 보면, **When** 페이지네이션이 표시되면, **Then** 번호 버튼(1~12)과 이전/다음 버튼이 작동한다

---

### User Story 2 — 아티클 상세 화면 열람 (Priority: P1)

블로그 방문자가 글 하나를 선택하면, 본문·사이드바·코드 블록·메트릭 카드 등이 포함된 상세 페이지를 볼 수 있다. 현재 `core/article-detail-dark.html` / `core/article-detail-light.html`과 시각적·기능적으로 동일해야 한다.

**Why this priority**: 아티클 상세 화면은 블로그의 핵심 가치를 전달하는 페이지다. 코드 블록, TOC 사이드바, 메트릭 카드 등 복잡한 요소가 많아 정확한 재현이 필수적이다.

**Independent Test**: 아티클 상세 화면만 단독 빌드하여 브라우저에서 열고, 기존 HTML 화면과 동일한 레이아웃·컴포넌트·인터랙션이 재현되는지 시각적으로 비교할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 아티클 상세 URL에 접속, **When** 페이지가 로드되면, **Then** 2열 레이아웃(본문 8열 + 사이드바 4열)이 표시된다
2. **Given** 아티클 상세 화면이 로드됨, **When** 상단을 보면, **Then** 카테고리 배지(SYSTEM_ARCHITECTURE, BACKEND 등), 제목(fade-in 애니메이션), 메타 정보(날짜, 읽기 시간, 태그)가 표시된다
3. **Given** 본문을 스크롤하면, **When** 코드 블록 섹션에 도달하면, **Then** 터미널 스타일 헤더(3색 도트, 파일명 레이블)와 구문 강조된 코드가 표시된다
4. **Given** 사이드바를 보면, **When** 페이지가 로드되면, **Then** 목차(TOC) 패널이 고정(sticky) 상태로 표시되며, 번호가 매겨진 항목과 활성 상태 하이라이트가 보인다
5. **Given** 본문 하단을 보면, **When** 이전/다음 글 네비게이션이 표시되면, **Then** 호버 시 좌/우 액센트 바가 나타나고 제목 색상이 변경된다
6. **Given** 메트릭 카드 영역을 보면, **When** 3열 그리드의 카드(P99_LATENCY, THROUGHPUT, ERROR_RATE)가 표시되면, **Then** 호버 시 보더 색상과 레이블 색상이 변경된다

---

### User Story 3 — Dark/Light 테마 전환 (Priority: P1)

블로그 방문자가 테마를 전환하면, 동일한 레이아웃과 콘텐츠를 유지한 채 색상 팔레트만 변경된다.

**Why this priority**: 테마 전환은 이 블로그의 핵심 경험이다. 헌법(constitution)에서도 "dark/light 쌍이 곧 제품 자체"라고 명시하며, 한쪽만 업데이트되고 다른 쪽이 방치되는 것은 반제품 출시와 동일하다.

**Independent Test**: 테마를 전환한 뒤 동일 화면의 DOM 구조와 콘텐츠가 동일하고, 색상 팔레트만 변경되었는지 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 dark 테마의 홈 화면을 보고 있을 때, **When** 테마를 light로 전환하면, **Then** 레이아웃·콘텐츠·인터랙션은 완전히 동일하며 배경색·텍스트색·액센트색 등 색상 팔레트만 변경된다
2. **Given** 사용자가 아티클 상세 화면에서 테마를 전환하면, **When** 전환이 완료되면, **Then** 코드 블록·TOC·메트릭 카드 등 모든 요소의 색상이 해당 테마에 맞게 변경되고, 내용·구조는 동일하다
3. **Given** dark 테마에서, **When** 네비게이션 바를 확인하면, **Then** 로고·링크·버튼의 색상이 dark 팔레트(네온 그린 계열 액센트)를 따르고, light 전환 시 light 팔레트(다크 그린 계열 액센트)로 변경된다

---

### User Story 4 — 공유 UI 요소 일관성 (Priority: P1)

블로그 운영자(개발자)가 네비게이션 바의 메뉴 항목을 하나 수정하면, 홈과 아티클 상세의 dark/light 버전 4곳 모두에 자동으로 반영된다.

**Why this priority**: 현재 4개 HTML 파일에 동일한 UI 요소가 복사-붙여넣기 되어 있어, 하나를 수정하면 나머지 3개를 놓치기 쉽다. 이것이 이 기능의 근본적 동기이다.

**Independent Test**: 공유 UI 요소(네비게이션 바 메뉴 텍스트)를 한 곳에서 수정한 뒤, 4개 화면 모두에서 변경이 반영되었는지 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 네비게이션 바가 공유 요소로 관리되고 있을 때, **When** 메뉴 항목 텍스트를 변경하면, **Then** 홈(dark/light)과 아티클 상세(dark/light) 4개 화면 모두에서 동일한 변경이 반영된다
2. **Given** 푸터가 공유 요소로 관리되고 있을 때, **When** 푸터 링크를 추가하면, **Then** 모든 화면에서 동일한 링크가 표시된다
3. **Given** 블로그 카드 컴포넌트가 공유 요소로 관리되고 있을 때, **When** 카드의 호버 애니메이션을 수정하면, **Then** 해당 카드를 사용하는 모든 화면에서 동일한 애니메이션이 적용된다

---

### Edge Cases

- 캐러셀이 마지막 슬라이드에 도달한 상태에서 다음 버튼을 누르면 첫 번째 슬라이드로 순환해야 한다
- 브라우저 창을 모바일 너비(375px)로 줄이면, 3열 카드 그리드가 1열로 축소되고 캐러셀·네비게이션이 반응형으로 조정되어야 한다
- 아티클 상세의 2열 레이아웃은 모바일에서 1열로 변경되며, 사이드바 TOC는 본문 아래로 이동해야 한다
- 네비게이션 바의 글래스모피즘(반투명 블러) 효과는 스크롤 시에도 유지되어야 한다
- 텍스트 선택(selection) 색상은 아티클 상세 화면에서 녹색 계열로 표시되어야 한다

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 홈 화면을 제공해야 한다 — 고정 네비게이션 바, 히어로 캐러셀(3장, 8초 자동 재생, 이전/다음 버튼, 인디케이터), "Entry Stream" 블로그 카드 그리드(3열 반응형), 페이지네이션, 푸터 포함
- **FR-002**: 시스템은 아티클 상세 화면을 제공해야 한다 — 2열 레이아웃(본문 + 사이드바), 카테고리 배지, 제목(fade-in 애니메이션), 메타 정보, 피처드 이미지(grayscale-to-color 호버), 코드 블록(터미널 스타일), 메트릭 카드(3열 그리드), 이전/다음 글 네비게이션, 고정 TOC 사이드바
- **FR-003**: 시스템은 dark/light 두 가지 테마를 지원해야 하며, 테마 전환 시 레이아웃과 콘텐츠는 동일하게 유지되고 색상 팔레트만 변경되어야 한다
- **FR-004**: 네비게이션 바, 푸터, 블로그 카드, 캐러셀, 페이지네이션, 코드 블록, 메트릭 카드, TOC 사이드바 등 반복되는 UI 요소는 단일 소스에서 관리되어, 하나를 수정하면 해당 요소를 사용하는 모든 화면에 반영되어야 한다
- **FR-005**: 홈 화면과 아티클 상세 화면은 각각 독립적으로 개발·빌드·검증이 가능해야 한다
- **FR-006**: 네비게이션 바는 상단 고정(sticky) 상태로, 반투명 배경에 블러(glassmorphism) 효과를 유지해야 한다
- **FR-007**: dark 테마의 홈 화면에서 블로그 카드 호버 시 텍스트에 녹색 글로우(glow) 효과가 나타나야 한다 (dark 전용 인터랙션)
- **FR-008**: 아티클 상세 화면의 피처드 이미지는 기본 grayscale 상태에서 호버 시 풀 컬러로 전환되어야 한다
- **FR-009**: 모든 화면은 반응형이어야 한다 — 데스크탑(3열 그리드), 태블릿(2열), 모바일(1열)로 카드 레이아웃이 조정되고, 아티클 상세의 2열 레이아웃은 모바일에서 1열로 변경되어야 한다
- **FR-010**: 타이포그래피는 Inter(제목/본문)와 JetBrains Mono(레이블/코드/메타 정보) 두 폰트만 사용해야 한다
- **FR-011**: 바디 배경에 32px 간격의 미세한 그리드 패턴이 표시되어야 한다 (dark: 흰색 미세 선, light: 검정 미세 선)
- **FR-012**: 푸터는 "Revi Blog" 텍스트, 동적 저작권 연도, About/GitHub/LinkedIn 외부 링크를 포함해야 한다

### Key Entities

- **화면(Screen)**: 사용자에게 보여지는 전체 페이지 단위 — 홈, 아티클 상세
- **테마(Theme)**: 화면의 색상 팔레트 변형 — dark(네이비 배경, 네온 그린 액센트), light(화이트 배경, 다크 그린 액센트)
- **공유 UI 요소(Shared UI Element)**: 여러 화면에서 재사용되는 독립적 UI 블록 — 네비게이션 바, 푸터, 블로그 카드, 캐러셀, 페이지네이션, 코드 블록, 메트릭 카드, TOC 사이드바
- **블로그 카드(Blog Card)**: 홈 화면에서 글 목록을 보여주는 단위 — 썸네일, 제목, 날짜, 화살표 아이콘으로 구성
- **아티클(Article)**: 블로그 글 본문 — 카테고리, 제목, 메타 정보, 피처드 이미지, 본문 콘텐츠, 코드 블록, 메트릭 카드로 구성

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 재구현된 홈 화면의 시각적 출력이 기존 `core/home-dark.html` / `core/home-light.html`과 픽셀 수준에서 동일하다 (레이아웃, 색상, 간격, 폰트 크기 등)
- **SC-002**: 재구현된 아티클 상세 화면의 시각적 출력이 기존 `core/article-detail-dark.html` / `core/article-detail-light.html`과 동일하다
- **SC-003**: 공유 UI 요소(네비게이션 바, 푸터 등)를 한 곳에서 수정했을 때, 변경 사항이 모든 화면(홈 dark/light, 아티클 상세 dark/light)에 반영되는 데 추가 수정이 필요 없다 (수정 지점 1곳)
- **SC-004**: 테마 전환 시 페이지 레이아웃과 콘텐츠가 100% 동일하게 유지된다 (DOM 구조 일치)
- **SC-005**: 홈 화면을 아티클 상세와 독립적으로 빌드·실행했을 때 모든 기능이 정상 작동한다
- **SC-006**: 아티클 상세 화면을 홈과 독립적으로 빌드·실행했을 때 모든 기능이 정상 작동한다
- **SC-007**: 캐러셀·페이지네이션·카드 호버·TOC 등 기존 인터랙션이 재구현 후에도 모두 동일하게 작동한다

## Assumptions

- 기존 `core/*.html` 4개 파일이 디자인의 최종 기준(source of truth)이다 — 재구현은 이 파일들의 시각적 출력을 정확히 복제하는 것을 목표로 한다
- 현재 HTML에 테마 토글 버튼이 없으므로, 테마 전환 메커니즘은 구현 단계에서 결정한다 (단, 동일 URL에서 전환 가능해야 함)
- 블로그 카드와 아티클의 실제 데이터(제목, 날짜, 이미지 등)는 현재 HTML에 하드코딩된 샘플 데이터를 그대로 사용한다 — 동적 데이터 연동은 이 기능의 범위 밖이다
- 외부 링크(About → me.revi1337.com, GitHub, LinkedIn)는 기존과 동일한 URL을 유지한다
- dark 테마에서만 존재하는 터미널 글로우 효과는 dark 테마 전용 인터랙션으로 유지한다
- 반응형 브레이크포인트는 기존 HTML에서 사용된 값을 따른다 (중간: 768px, 대형: 1024px)
- 기존 HTML 간의 미세한 불일치(dark/light 간 borderRadius 차이, font weight 차이 등)는 재구현 시 통일하여 일관성을 확보한다
