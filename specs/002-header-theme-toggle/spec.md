# Feature Specification: 헤더 Nav Dark/Light 토글 버튼 추가

**Feature Branch**: `002-header-theme-toggle`

**Created**: 2026-07-20

**Status**: Draft

**Input**: User description: "프로젝트에서 공통으로 사용되는 Header Nav 의 Login 버튼 오른쪽에 dark/light 토글 버튼을 만들어야해. me.revi1337.com 의 헤더에 있는 토글 svg와 효과 모두 완벽히 동일해야해. 뿐만아니라, 토글 버튼 옆에 있는 | 같은 delimiter 도 완벽히 동일해야해."

## User Scenarios & Testing *(mandatory)*

### User Story 1 — 버튼 클릭으로 테마 전환 (Priority: P1)

블로그 방문자가 공통 헤더 네비게이션의 LOGIN 버튼 오른쪽에 있는 테마 토글 버튼을 클릭하면, 페이지 리로드 없이 dark ↔ light 테마가 즉시 전환된다.

**Why this priority**: 이 기능의 핵심 목적이다. 현재 프로젝트는 홈/아티클 상세를 포함한 모든 화면에서 공통 헤더를 사용하므로, 토글 버튼 하나로 사이트 전체의 테마를 즉시 전환할 수 있어야 한다.

**Independent Test**: 아무 페이지(홈 또는 아티클 상세)에서 헤더의 테마 토글 버튼을 클릭한 뒤, 페이지 리로드 없이 배경색·텍스트색·액센트색이 즉시 변경되는지 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** dark 테마 상태의 페이지를 보고 있을 때, **When** 헤더의 테마 토글 버튼을 클릭하면, **Then** 페이지 리로드 없이 light 테마로 즉시 전환된다 (배경색, 텍스트색, 액센트색, 보더 등 모든 색상 토큰이 변경됨)
2. **Given** light 테마 상태의 페이지를 보고 있을 때, **When** 헤더의 테마 토글 버튼을 클릭하면, **Then** 페이지 리로드 없이 dark 테마로 즉시 전환된다
3. **Given** 테마가 전환된 상태에서, **When** 같은 사이트 내 다른 페이지로 이동하면, **Then** 선택한 테마가 유지된다

---

### User Story 2 — 레퍼런스 사이트와 완벽히 동일한 토글 디자인 (Priority: P1)

토글 버튼은 LOGIN 버튼 바로 오른쪽에 배치되며, 아이콘(SVG) 모양, 클릭/호버 인터랙션, 그리고 토글 옆의 구분선(`|`)까지 https://me.revi1337.com 헤더와 픽셀 단위로 동일하다.

**Why this priority**: 사용자가 명시적으로 "완벽히 동일"을 요구했다. 근사치 재현은 이 기능의 인수 기준을 만족하지 못하며, 디자인 일관성은 이 블로그 브랜드의 핵심 요구사항이다.

**Independent Test**: 재구현된 헤더의 LOGIN 버튼-구분선-토글 버튼 영역을 레퍼런스 사이트(me.revi1337.com)의 동일 영역과 나란히 놓고 스크린샷으로 비교하여, 아이콘 모양·크기·간격·구분선 스타일·호버 상태가 시각적으로 구분 불가능함을 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 헤더 네비게이션 바를 보면, **When** LOGIN 버튼 오른쪽 영역을 확인하면, **Then** LOGIN 버튼과 토글 버튼 사이에 레퍼런스 사이트와 동일한 형태·색상·굵기·여백의 구분선(`|`)이 표시된다
2. **Given** dark 테마 상태에서, **When** 토글 버튼의 아이콘을 확인하면, **Then** 레퍼런스 사이트와 동일한 태양(light 전환용) 아이콘 SVG가 동일한 모양·크기로 표시된다
3. **Given** light 테마 상태에서, **When** 토글 버튼의 아이콘을 확인하면, **Then** 레퍼런스 사이트와 동일한 달(dark 전환용) 아이콘 SVG가 동일한 모양·크기로 표시된다
4. **Given** 토글 버튼 위에 마우스를 올리면, **When** 호버 상태가 되면, **Then** 레퍼런스 사이트와 동일한 호버 인터랙션(아이콘/배경 색상 변화 등)이 나타난다
5. **Given** 토글 버튼을 클릭하면, **When** 테마가 전환되는 순간, **Then** 레퍼런스 사이트와 동일한 전환 애니메이션(아이콘 모양 변경 방식, 트랜지션 속도·이징)이 재생된다
6. **Given** 토글 버튼과 구분선을 확인하면, **When** 레퍼런스 사이트와 비교하면, **Then** 클릭 가능 영역, 아이콘 크기, 구분선과 좌우 요소 간 여백이 모두 동일하다

### User Story 3 — 테마 선택 기억 (Priority: P2)

블로그 방문자가 테마를 선택한 뒤 브라우저를 닫고 다시 방문하면, 이전에 선택한 테마가 적용된다.

**Why this priority**: 사용자 경험의 연속성을 위해 중요하지만, 핵심 전환 기능과 동일 디자인 재현(P1)이 먼저 완성되어야 한다.

**Independent Test**: 테마를 전환한 뒤 브라우저를 닫고, 동일한 페이지를 다시 열어 이전 테마가 유지되는지 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 light 테마로 전환한 상태에서, **When** 브라우저를 닫고 같은 페이지를 다시 방문하면, **Then** light 테마가 유지된다
2. **Given** 사용자가 처음 방문(저장된 선택 없음)할 때, **When** 페이지가 로드되면, **Then** 시스템 기본 설정(OS 테마) 또는 dark 테마가 기본값으로 적용된다

---

### Edge Cases

- 헤더가 공통 컴포넌트로 모든 화면(홈, 아티클 상세 등)에 렌더링되므로, 어느 화면에서 토글하든 동일한 위치·디자인·동작을 보여야 한다
- 테마 전환 시 진행 중인 CSS 애니메이션(캐러셀 자동 재생 등)이 중단되지 않아야 한다
- 아티클 상세 페이지의 코드 블록, 메트릭 카드, TOC 사이드바 등 모든 요소가 테마 전환에 정확히 반응해야 한다
- dark 테마 전용 효과(터미널 글로우)는 light 전환 시 비활성화되고, dark로 돌아오면 다시 활성화되어야 한다
- 빠르게 연속 클릭(더블·트리플 클릭)해도 최종 상태가 정확해야 하며, 전환 애니메이션이 겹치거나 깨지지 않아야 한다
- 모바일 뷰포트에서도 LOGIN 버튼·구분선·토글 버튼이 접근 가능하고 터치 가능해야 한다
- 화면 너비가 좁아져 네비게이션 메뉴가 축약되는 경우에도, LOGIN 버튼-구분선-토글 버튼 그룹의 상대적 배치와 간격은 유지되어야 한다

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 공통 헤더 네비게이션의 LOGIN 버튼 바로 오른쪽에 테마 토글 버튼을 표시해야 한다
- **FR-002**: LOGIN 버튼과 토글 버튼 사이에는 레퍼런스 사이트(me.revi1337.com)와 형태·색상·굵기·여백이 동일한 구분선(`|`)이 표시되어야 한다
- **FR-003**: 토글 버튼의 아이콘 SVG는 레퍼런스 사이트와 동일한 모양·크기를 가져야 한다 — dark 테마에서는 light 전환용 아이콘(태양), light 테마에서는 dark 전환용 아이콘(달)을 표시한다
- **FR-004**: 토글 버튼 클릭 시 페이지 리로드 없이 dark ↔ light 테마가 즉시 전환되어야 한다 — 배경색, 텍스트색, 액센트색, 보더 색상 등 모든 색상 토큰이 변경된다
- **FR-005**: 토글 버튼의 호버 효과와 클릭 시 전환 애니메이션(아이콘 변경 방식, 트랜지션 속도·이징)은 레퍼런스 사이트와 동일해야 한다
- **FR-006**: 토글 버튼과 구분선은 클릭 가능 영역, 아이콘 크기, 좌우 여백이 레퍼런스 사이트와 동일해야 한다
- **FR-007**: 사용자가 선택한 테마는 브라우저 세션 간에 유지되어야 한다 (재방문 시 이전 선택 적용)
- **FR-008**: 사용자의 저장된 테마 선택이 없을 경우, 운영체제의 시스템 테마 설정을 따르되 이것도 없으면 dark 테마를 기본값으로 적용해야 한다
- **FR-009**: 테마 전환 시 홈 화면과 아티클 상세 화면의 모든 UI 요소(네비게이션 바, 캐러셀, 카드, 코드 블록, TOC, 메트릭 카드, 푸터 등)가 정확하게 색상을 변경해야 한다
- **FR-010**: 같은 사이트 내 페이지 간 이동 시 현재 선택된 테마가 유지되어야 한다
- **FR-011**: 토글 버튼은 접근성을 위한 적절한 레이블을 가져야 한다 — dark 상태에서 "라이트 모드로 전환", light 상태에서 "다크 모드로 전환" 등
- **FR-012**: LOGIN 버튼-구분선-토글 버튼 그룹은 헤더가 사용되는 모든 화면(홈, 아티클 상세 등)에서 동일한 위치·크기·동작으로 표시되어야 한다 (공유 UI 요소로 관리)

### Key Entities

- **테마 선택(Theme Preference)**: 사용자가 현재 보고 있는(또는 마지막으로 선택한) 테마 값(dark/light)을 나타내며, 세션 간 유지되는 저장된 상태와 현재 적용된 상태를 함께 가진다

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 테마 토글 버튼을 1회 클릭하면 0.3초 이내에 전체 화면의 색상이 전환된다 (체감 즉시)
- **SC-002**: LOGIN 버튼-구분선-토글 버튼 영역을 레퍼런스 사이트(me.revi1337.com)와 나란히 스크린샷 비교했을 때, 아이콘 모양·크기·간격·구분선 스타일·호버 및 전환 애니메이션이 육안상 구분 불가능하다
- **SC-003**: 테마를 선택한 뒤 브라우저를 닫고 재방문했을 때 100% 이전 선택이 유지된다
- **SC-004**: 테마 전환 후 화면의 모든 UI 요소가 해당 테마의 색상 팔레트를 정확히 반영한다 (누락된 요소 0개)
- **SC-005**: 토글 버튼 클릭 시 페이지 리로드가 발생하지 않는다 (네트워크 요청 0건)

## Assumptions

- 레퍼런스 사이트(me.revi1337.com)의 토글 버튼과 구분선은 구현 단계에서 실제로 접속·검사(DOM/CSS/애니메이션 확인)하여 재현하며, 이 스펙은 그 시각적 요구사항(동일한 SVG, 동일한 효과, 동일한 구분선)을 명시하는 데 집중한다
- 테마 선택 저장은 브라우저의 로컬 저장소를 활용하며, 서버 측 저장은 범위 밖이다
- 테마 전환 시 색상 팔레트만 변경되며, 페이지 구조나 레이아웃은 변경되지 않는다
- 토글 버튼의 접근성 레이블은 한국어로 제공한다 ("라이트 모드로 전환" / "다크 모드로 전환")
- 초기 페이지 로드 시 테마가 깜빡이는 현상(flash of unstyled content)이 발생하지 않아야 한다
- 이 기능은 공통 헤더 네비게이션(LOGIN 버튼 포함)이 이미 모든 화면에 적용되어 있다는 전제 위에서 구현된다
