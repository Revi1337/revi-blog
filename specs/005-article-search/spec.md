# Feature Specification: 아티클 통합 검색

**Feature Branch**: `005-article-search`

**Created**: 2026-07-21

**Status**: Draft

**Input**: User description: "블로그 헤더에 검색 입력창 모양의 트리거를 추가해서, 방문자가 아티클을 '제목/본문 내용/태그'로 찾을 수 있는 통합 검색 기능을 만들어야 해. 헤더 nav의 검색 트리거는 실제 입력 필드처럼 생겼지만 텍스트를 바로 입력받지는 않고, 클릭하면(또는 Ctrl+K / Cmd+K 단축키를 누르면) 검색 모달이 열리는 방식이야. 트리거 안에는 검색 기능임을 알려주는 placeholder 문구와, 오른쪽에 Ctrl+K 단축키를 알려주는 뱃지가 항상 노출되어야 해. 검색 트리거와 검색 모달의 스타일은 dark/light 테마를 그대로 따라야 하고, 테마 전환 시 즉시 반영되어야 해. 모달이 열리면 일반 텍스트로 제목/본문을 실시간 검색하고, #태그명 형식으로 태그 검색을 지원해야 해. 텍스트 검색은 제목 매치를 본문 매치보다 우선 정렬하고, 태그 검색은 랭킹 없이 전부 노출해야 해. 결과는 개수 제한 없이 스크롤 가능한 리스트로 보여주고, 매치가 없으면 영어 안내 문구를 노출해야 해. 홈 화면 노출이 꺼진 아티클은 검색 대상에서 제외해야 해. 검색은 대소문자 구분 없는 부분 문자열 매칭이며 오타 허용이나 형태소 분석은 범위 밖이야. 모바일에서도 동일한 트리거를 쓰되 모달은 전체 화면으로 표시돼야 하고, 입력을 멈춘 뒤 결과가 체감상 즉시 나타나야 해."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 제목/본문 텍스트로 아티클 찾기 (Priority: P1)

방문자가 헤더의 검색 트리거를 클릭하거나 Ctrl+K(Mac에서는 Cmd+K)를 눌러 검색 모달을 열고, 찾고 싶은 아티클과 관련된 일반 텍스트를 입력하면 제목 또는 본문 내용에 해당 텍스트가 포함된 아티클이 실시간으로 결과 리스트에 나타난다.

**Why this priority**: 이 기능의 핵심 가치. 검색 트리거의 노출과 텍스트 검색이 동작하지 않으면 나머지 요구사항(태그 검색, 테마 대응, 모바일 대응)은 의미가 없다.

**Independent Test**: 헤더에서 검색 트리거를 클릭해 모달을 열고, 특정 아티클 제목에 포함된 단어를 입력했을 때 해당 아티클이 결과 최상단에 나타나는지, 본문에만 포함된 단어를 입력했을 때도 결과에 나타나는지 확인하는 것만으로 완결적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 방문자가 아무 페이지에서나 헤더를 보고 있음, **When** 헤더 nav를 확인함, **Then** 검색 트리거가 입력 필드 모양으로 보이고 그 안에 검색 안내 placeholder 문구와 우측에 Ctrl+K 단축키 뱃지가 항상 노출되어 있다.
2. **Given** 검색 모달이 닫혀 있음, **When** 방문자가 검색 트리거를 클릭하거나 Ctrl+K(Cmd+K)를 누름, **Then** 검색 모달이 열리고 텍스트를 입력할 수 있는 입력창에 포커스가 간다.
3. **Given** 검색 모달이 열려 있고 입력창이 비어 있음, **When** 방문자가 어떤 아티클의 제목에 포함된 단어를 입력함, **Then** 해당 단어를 대소문자 구분 없이 제목에 포함하는 아티클들이 결과 리스트 상단에 나타난다.
4. **Given** 검색 모달이 열려 있음, **When** 방문자가 제목에는 없지만 특정 아티클 본문에만 포함된 단어를 입력함, **Then** 해당 아티클이 결과 리스트에 나타나되, 같은 검색어가 제목에 매치된 아티클보다 아래에 위치한다.
5. **Given** 검색 결과 리스트가 표시됨, **When** 방문자가 결과 중 하나를 선택함, **Then** 검색 모달이 닫히고 해당 아티클 상세 화면으로 이동한다.
6. **Given** 검색 모달이 열려 있음, **When** 방문자가 어떤 아티클의 제목·본문에도 포함되지 않는 검색어를 입력함, **Then** "No results found." 문구가 표시된다.
7. **Given** 검색 결과 리스트가 표시됨, **When** 방문자가 키보드 방향키(↑/↓)로 항목을 이동한 뒤 `Enter`를 누름, **Then** 마우스 클릭 없이도 선택된 항목의 아티클 상세 화면으로 이동한다.

---

### User Story 2 - #태그명으로 아티클 찾기 (Priority: P2)

방문자가 검색 모달의 입력창에 `#태그명` 형식으로 입력하면, 일반 텍스트 검색과 별개로 해당 태그가 붙은 아티클이 랭킹 없이 모두 결과로 나타난다. 모달을 처음 열었을 때 이 태그 검색 문법을 알려주는 힌트가 노출되어 있어, 방문자가 이 기능의 존재를 스스로 발견할 수 있다.

**Why this priority**: 제목/본문 검색(P1)만으로도 핵심 가치는 제공되지만, 태그 검색은 사용자가 발견 없이는 존재를 알 수 없는 부가 문법이므로 힌트 노출과 함께 별도로 검증되어야 한다.

**Independent Test**: 검색 모달을 새로 열었을 때 태그 검색 힌트가 보이는지 확인하고, `#태그명`을 입력했을 때 해당 태그가 붙은 아티클만(랭킹 없이) 모두 나타나는지, 일반 텍스트 검색 결과와 섞이지 않는지 확인하는 것으로 완결적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 방문자가 검색 트리거를 통해 검색 모달을 처음 엶, **When** 아직 아무것도 입력하지 않음, **Then** `#태그명` 형식으로 태그 검색이 가능하다는 힌트 문구가 노출된다.
2. **Given** 검색 모달이 열려 있음, **When** 방문자가 `#`으로 시작하는 태그명(예: `#backend`)을 입력함, **Then** 해당 태그가 붙어 있는 아티클이 특정 순서 없이 모두 결과 리스트에 나타난다.
3. **Given** 검색 모달이 열려 있음, **When** 방문자가 `#`으로 시작하는 검색어를 입력함, **Then** 제목이나 본문에만 해당 문자열이 포함되고 태그로는 붙어 있지 않은 아티클은 결과에 나타나지 않는다.
4. **Given** 태그 검색 결과가 표시됨, **When** 어떤 아티클에도 붙어 있지 않은 태그명을 입력함, **Then** "No results found." 문구가 표시된다.

---

### User Story 3 - 다크/라이트 테마를 따라가는 검색 UI (Priority: P3)

방문자가 헤더 토글로 선택한 dark/light 테마에 맞춰 검색 트리거와 검색 모달의 스타일이 항상 일치하며, 검색 모달이 열려 있는 상태에서 테마를 전환해도 페이지의 다른 요소들과 동시에 색상이 바뀐다.

**Why this priority**: 검색 UI 자체의 동작(P1, P2)에는 영향을 주지 않는 시각적 일관성 요구사항이지만, 다크/라이트 테마 쌍을 항상 함께 유지해야 하는 이 프로젝트의 원칙상 별도로 검증할 가치가 있다.

**Independent Test**: 라이트 테마에서 검색 모달을 열어 스타일을 확인하고, 모달이 열린 채로 테마를 다크로 전환했을 때 모달 색상이 다른 페이지 요소와 함께 즉시 바뀌는지 확인하는 것으로 완결적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 방문자가 라이트 테마를 사용 중임, **When** 검색 트리거와 검색 모달을 확인함, **Then** 둘 다 라이트 테마 색상 체계를 따른다.
2. **Given** 방문자가 다크 테마를 사용 중임, **When** 검색 트리거와 검색 모달을 확인함, **Then** 둘 다 다크 테마 색상 체계를 따른다.
3. **Given** 검색 모달이 열려 있음, **When** 방문자가 헤더의 테마 토글을 눌러 테마를 전환함, **Then** 검색 모달의 색상이 페이지의 다른 요소들과 동시에 새 테마로 전환된다.

---

### User Story 4 - 모바일에서 검색 사용하기 (Priority: P4)

모바일 화면에서도 헤더의 검색 트리거를 데스크톱과 동일하게 사용할 수 있으며, 트리거를 탭하면 검색 모달이 화면 전체를 채우는 형태로 열린다.

**Why this priority**: 데스크톱에서의 핵심 검색 동작(P1, P2)이 먼저 완성되어야 의미가 있는, 뷰포트별 레이아웃 대응 요구사항이다.

**Independent Test**: 모바일 뷰포트에서 헤더의 검색 트리거가 보이는지, 탭했을 때 모달이 화면 전체를 채우며 열리는지, 그 안에서 텍스트/태그 검색이 데스크톱과 동일하게 동작하는지 확인하는 것으로 완결적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 방문자가 모바일 화면 너비로 사이트를 보고 있음, **When** 헤더를 확인함, **Then** 검색 트리거가 동일하게 노출되어 있다.
2. **Given** 모바일 화면임, **When** 방문자가 검색 트리거를 탭함, **Then** 검색 모달이 화면 전체를 채우는 형태로 열린다.
3. **Given** 모바일에서 검색 모달이 열려 있음, **When** 방문자가 검색어 또는 `#태그명`을 입력함, **Then** 데스크톱과 동일한 방식으로 결과가 나타난다.

---

### Edge Cases

- 검색 모달을 열자마자(입력값이 빈 문자열일 때) 결과 리스트는 비어 있고, `#태그명` 힌트만 노출된다.
- 방문자가 `#`만 입력하고 태그명을 입력하지 않으면 결과가 없는 상태(`No results found.`)로 처리된다.
- 검색어가 공백만으로 이루어진 경우, 결과가 없는 상태로 처리된다.
- 홈 화면 노출이 꺼진 아티클은 텍스트 검색·태그 검색 어느 쪽으로도 결과에 나타나지 않는다.
- 검색어가 대문자/소문자가 섞여 있어도 매치 여부에는 영향을 주지 않는다.
- 결과 리스트가 화면에 다 들어가지 않을 만큼 많을 때, 리스트 자체가 스크롤되며 개수는 제한되지 않는다.
- 검색 모달이 열려 있는 도중 방문자가 테마를 전환하면, 모달을 닫았다 다시 열지 않아도 새 테마 색상이 즉시 반영된다.
- 방문자가 Esc를 누르거나 모달 바깥 영역을 클릭하면 모달이 닫힌다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 헤더 nav 안에 실제 입력 필드처럼 보이는 검색 트리거를 항상 노출해야 한다.
- **FR-002**: 검색 트리거는 검색 기능을 안내하는 placeholder 문구와, 우측에 `Ctrl+K` 단축키를 알려주는 뱃지를 항상 함께 노출해야 한다.
- **FR-003**: 검색 트리거는 텍스트를 직접 입력받지 않으며, 클릭 시 검색 모달을 열어야 한다.
- **FR-004**: 시스템은 `Ctrl+K`(Windows/Linux) 및 `Cmd+K`(Mac) 단축키로 검색 모달을 열 수 있어야 한다.
- **FR-005**: 검색 트리거와 검색 모달은 방문자가 헤더 토글로 선택한 dark/light 테마를 그대로 따라야 하며, 별도로 고정된 스타일을 갖지 않는다.
- **FR-006**: 검색 모달이 열려 있는 상태에서 테마가 전환되면, 모달의 색상은 페이지의 다른 요소와 동시에 새 테마로 전환되어야 한다.
- **FR-007**: 검색 모달은 입력값이 없을 때 `#태그명` 형식의 태그 검색이 가능함을 알리는 힌트를 노출해야 한다.
- **FR-008**: 입력값이 `#`으로 시작하지 않는 경우, 시스템은 이를 일반 텍스트 검색어로 취급하여 아티클 제목과 본문 내용을 대상으로 검색해야 한다.
- **FR-009**: 일반 텍스트 검색은 태그를 검색 대상에 포함하지 않아야 한다.
- **FR-010**: 입력값이 `#`으로 시작하는 경우, 시스템은 `#` 다음에 오는 문자열을 태그명으로 취급하여 해당 문자열을 포함하는 태그가 붙은 아티클만 결과로 반환해야 하며, 이때 제목·본문은 검색 대상에서 제외해야 한다.
- **FR-011**: 일반 텍스트 검색 결과는 검색어가 제목에 매치된 아티클을 본문에만 매치된 아티클보다 항상 위에 정렬해야 한다.
- **FR-012**: 태그 검색 결과는 별도의 랭킹 없이 매치되는 모든 아티클을 반환해야 한다.
- **FR-013**: 두 검색 모드(텍스트/태그) 모두 결과 개수를 제한하지 않고, 스크롤 가능한 리스트로 전체 결과를 보여줘야 한다.
- **FR-014**: 매치되는 아티클이 하나도 없을 때, 시스템은 영어로 된 "No results found." 안내 문구를 표시해야 한다.
- **FR-015**: 검색은 대소문자를 구분하지 않고, 검색어가 대상 필드(제목/본문/태그)의 일부 문자열과 일치하면 결과에 포함해야 한다.
- **FR-016**: 검색은 오타 허용(fuzzy matching)이나 한국어 형태소 분석 수준의 매칭을 제공하지 않는다.
- **FR-017**: 시스템은 홈 화면 노출이 꺼진 아티클을 텍스트 검색과 태그 검색 결과 모두에서 제외해야 한다.
- **FR-018**: 방문자가 텍스트를 입력하는 동안(또는 입력을 멈춘 직후) 결과 리스트는 별도의 제출 동작 없이 실시간으로 갱신되어야 한다.
- **FR-019**: 방문자가 검색 결과 중 하나를 선택하면, 검색 모달이 닫히고 해당 아티클 상세 화면으로 이동해야 한다.
- **FR-020**: 모바일 화면에서도 헤더의 검색 트리거는 데스크톱과 동일하게 노출되고 동작해야 한다.
- **FR-021**: 모바일 화면에서 검색 모달은 화면 전체를 채우는 형태로 표시되어야 한다.
- **FR-022**: 방문자는 `Esc` 키를 누르거나 모달 바깥 영역을 클릭해 검색 모달을 닫을 수 있어야 한다.
- **FR-023**: 방문자는 결과 리스트에서 키보드 방향키(↑/↓)로 항목 간 이동을 할 수 있어야 하며, `Enter`로 현재 선택된 항목을 열 수 있어야 한다.

### Key Entities

- **아티클(검색 대상)**: 검색의 대상이 되는 콘텐츠. 제목, 본문 내용, 태그 목록, 홈 화면 노출 여부를 가진다. 홈 화면 노출 여부가 꺼져 있으면 검색 대상에서 완전히 제외된다.
- **검색어**: 방문자가 입력창에 입력하는 문자열. 첫 글자가 `#`인지 여부에 따라 "일반 텍스트 검색"과 "태그 검색" 두 모드 중 하나로 해석된다.
- **검색 결과 항목**: 검색어와 매치된 아티클 한 건. 일반 텍스트 검색에서는 매치 위치(제목/본문)에 따른 정렬 순서를 가지며, 태그 검색에서는 정렬 순서를 갖지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 방문자는 어떤 페이지에서든 헤더를 보는 즉시(추가 조작 없이) 검색 기능의 존재와 `Ctrl+K` 단축키를 인지할 수 있다.
- **SC-002**: 방문자가 검색어 입력을 멈춘 뒤 결과가 지연을 체감할 수 없을 정도로 즉시 나타난다.
- **SC-003**: 텍스트 검색 결과에서 제목이 매치된 아티클은 100% 본문만 매치된 아티클보다 위에 표시된다.
- **SC-004**: 검색 모달을 새로 여는 방문자 전원이 `#태그명` 문법 힌트를 별도 탐색 없이 확인할 수 있다.
- **SC-005**: 홈 화면 노출이 꺼진 아티클은 어떤 검색어를 입력하더라도 결과에 나타나지 않는다(노출률 0%).
- **SC-006**: 모바일 방문자는 데스크톱 방문자와 동일한 절차(트리거 탭 또는 단축키)로 검색을 시작할 수 있고, 모달은 화면 전체를 채운 상태로 표시된다.
- **SC-007**: 검색 모달이 열려 있는 동안 테마를 전환하면, 모달을 닫지 않고도 다른 페이지 요소와 동시에 새 테마 색상이 반영된다.
- **SC-008**: 매치되는 아티클이 없는 모든 검색어에 대해 "No results found." 안내 문구가 표시된다.

## Assumptions

- 태그 검색 판정은 입력값 전체가 아니라 "첫 글자가 `#`인지"로 결정한다. `#`으로 시작하면 입력값 전체가 태그 검색 모드로 전환되며, 같은 입력 안에서 일반 텍스트 검색과 태그 검색이 동시에 섞여 동작하지 않는다.
- 본문 검색 대상은 방문자에게 보이는 본문 텍스트 전체이며, 마크다운/서식 문법 자체(`**`, `#` 헤딩 기호 등)는 검색 대상 문자열에서 제외된 순수 텍스트로 간주한다.
- 검색 결과 항목을 클릭/탭하면 해당 아티클 상세 화면으로 이동하고 모달은 닫힌다 (별도 "모두 보기" 화면은 이번 범위에 포함하지 않는다).
- 검색 모달은 `Esc` 키 또는 바깥 영역 클릭으로 닫을 수 있다 — 이는 모달형 UI의 표준 동작이며 사용자 설명에 명시되지 않았지만 업계 표준 기본값으로 채택한다.
- 검색 모달은 Algolia DocSearch류의 커맨드 팔레트 패턴을 참조하며, 결과 리스트는 키보드 방향키(↑↓)로 이동하고 `Enter`로 선택할 수 있어야 한다 — 마우스/터치 클릭도 동일하게 지원하되, 키보드 탐색이 주된 상호작용 방식 중 하나로 포함된다.
- 검색은 클라이언트에서 체감 가능한 지연 없이 동작해야 한다는 정성적 기준만 요구되며, 별도의 사용률·응답시간 등 정량 트래킹 지표 수집은 이번 범위에 포함하지 않는다.
- 아티클 목록과 각 아티클의 홈 화면 노출 여부는 기존에 존재하는 콘텐츠 데이터를 그대로 재사용하며, 이번 기능을 위해 별도의 콘텐츠 필드를 추가하지 않는다.
