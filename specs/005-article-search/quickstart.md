# Quickstart: 아티클 통합 검색 검증

Phase 1 산출물. 이 기능이 실제로 동작하는지 사람이 브라우저에서 눈으로 확인하기 위한 가이드다(Constitution
Principle I). 구현 세부 코드나 완전한 테스트 스위트는 포함하지 않는다 — 세부 항목은 `/speckit-tasks`가
분해한다.

## Prerequisites

- 저장소 루트에서 의존성 설치: `npm install` (이번 기능이 `cmdk`를 새로 추가하므로 계획 반영 후 재설치
  필요)
- 로컬 서버 기동: `npm run dev` (기본 포트 3999)
- `content/articles/_syntax-preview.md`가 이미 `showOnHomepage: false`, `title: "Syntax Preview (내부
  검증용)"`, `tags: ["TEST"]`로 설정되어 있어 별도 준비 없이 제외 시나리오(6번) 검증에 바로 쓸 수 있다

## 검증 시나리오

spec.md의 Acceptance Scenarios를 그대로 따라간다. 괄호 안은 대응하는 FR/SC.

1. **트리거 상시 노출** (FR-001, FR-002, SC-001)
   - 아무 페이지나 열고 헤더를 확인한다.
   - 기대: 입력창 모양의 트리거가 보이고, 그 안에 검색 안내 placeholder와 우측에 `Ctrl+K` 뱃지가 항상
     보인다.

2. **모달 열기 — 클릭 / 단축키** (FR-003, FR-004)
   - 트리거를 클릭한다 → 모달이 열리고 입력창에 포커스가 간다.
   - 모달을 닫고 `Ctrl+K`(macOS는 `Cmd+K`)를 누른다 → 동일하게 열린다.
   - 다른 입력 필드(있다면)에 포커스가 가 있는 상태에서 `k`를 눌러본다 → 모달이 열리지 않아야 한다.

3. **텍스트 검색 + 랭킹** (FR-008, FR-009, FR-011, SC-002, SC-003)
   - 특정 아티클 제목에만 있는 단어를 입력 → 해당 아티클이 결과에 즉시 나타난다.
   - 제목에는 없고 본문에만 있는 단어를 입력 → 결과에 나타나되, 같은 단어가 제목에 매치되는 다른
     아티클이 있다면 그보다 아래에 위치한다.
   - 입력을 멈춘 뒤 결과 갱신까지 눈에 띄는 지연이 없어야 한다.

4. **태그 검색** (FR-007, FR-010, FR-012)
   - 모달을 새로 연 직후(입력값 없음) `#태그명` 힌트가 보이는지 확인한다.
   - `#`으로 시작해 실제 존재하는 태그(예: `#backend`, 콘텐츠에 맞게 조정)를 입력 → 해당 태그가 붙은
     아티클이 모두, 랭킹 없이 나타난다.
   - 같은 문자열이 제목/본문에는 있지만 태그로는 없는 경우, `#` 없이 입력했을 때만 나오고 `#`을 붙이면
     나오지 않는지 교차 확인한다.

5. **결과 없음** (FR-014, SC-008)
   - 어떤 아티클에도 없는 무작위 문자열을 입력 → "No results found."가 영어로 표시된다.
   - `#`만 입력(태그명 없음) → 마찬가지로 결과 없음 처리된다.

6. **홈 노출 제외 아티클 격리** (FR-017, SC-005)
   - `_syntax-preview.md`(`showOnHomepage: false`) 기준으로 `Syntax`(제목), 본문에만 있는 단어,
     `#TEST`(태그)를 각각 검색해본다 → 세 경우 모두 결과에 나타나지 않아야 한다.
   - (선택, 개발자 도구로 확인 가능하면) 네트워크 탭 / React DevTools에서 "Syntax Preview" 텍스트가
     클라이언트로 전달된 페이로드에 아예 없는지 확인한다.

7. **키보드 탐색** (FR-023)
   - 여러 결과가 뜬 상태에서 `↓`/`↑`로 항목을 이동 → 선택된 항목이 시각적으로 강조된다.
   - `Enter`를 누른다 → 마우스 없이 선택된 아티클 상세 화면으로 이동하고 모달이 닫힌다.

8. **닫기** (FR-022)
   - 모달이 열린 상태에서 `Esc`를 누른다 → 닫힌다.
   - 모달을 다시 열고 바깥 어두운 영역을 클릭한다 → 닫힌다.

9. **테마 동기화** (FR-005, FR-006, SC-007)
   - 라이트 테마에서 모달을 열어 색상을 확인한다.
   - 모달이 열린 채로 헤더 테마 토글을 눌러 다크로 전환한다 → 페이지의 다른 요소와 동시에 모달 색상도
     즉시 바뀐다(모달을 닫았다 열 필요 없음).

10. **모바일 전체화면** (FR-020, FR-021, SC-006)
    - 브라우저 뷰포트를 모바일 폭으로 줄이거나 `playwright-cli`의 모바일 에뮬레이션을 사용한다.
    - 트리거가 동일하게 보이는지 확인 → 탭하면 모달이 화면 전체를 채우는지 확인 → 그 안에서 텍스트/태그
      검색이 데스크톱과 동일하게 동작하는지 확인한다.

## 완료 기준

- 위 10개 시나리오가 모두 기대대로 동작한다.
- `npm run build`가 에러/경고 없이 통과한다.
- 콘솔에 새로 발생한 에러/경고가 없다.
