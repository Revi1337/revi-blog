# Feature Specification: 게시글 오디오 내레이션 재생

**Feature Branch**: `015-audio-narration`

**Created**: 2026-09-05

**Status**: Draft

**Input**: User description: "게시글 상세 페이지에 오디오 내레이션 재생 기능을 추가한다.

배경:
- 오디오 파일 자체는 이 기능이 만들지 않는다. 저자가 별도로(예: TTS 서비스 등을 통해)
  직접 준비한 오디오 파일의 URL을 게시글 작성 시 지정해두면, 그 값이 있는 게시글에서만
  재생 기능이 활성화된다. 값이 없는 게시글에는 재생 관련 UI가 전혀 노출되지 않는다.

노출 위치:
- 게시글 상세 페이지의 메타 정보 줄(작성일 · 수정일 · 읽는시간 · 조회수 등이 나열되는
  줄)에 재생 버튼을 추가한다.
- 이 버튼은 조회수 다음, 썸네일 버튼보다 앞에 위치한다.
- 기존의 다른 선택적 메타 항목들(예: 썸네일 버튼)과 마찬가지로, 해당 값이 없는 글에서는
  버튼 자체가 나타나지 않는다.

재생 동작:
- 메타 줄의 재생 버튼을 누르면 화면(뷰포트) 하단에 고정된 오디오 재생 컨트롤이 나타나면서
  재생이 시작된다. 이 컨트롤은 본문을 스크롤해도 화면에 계속 고정되어 있다.
- 컨트롤에는 다음이 포함된다: 재생/일시정지 전환 버튼, 현재까지 재생된 시간, 전체 재생
  시간, 원하는 지점으로 이동할 수 있는 진행 막대, 재생 속도 조절, 그리고 컨트롤 자체를
  닫는 버튼.
- 일시정지 버튼을 누르면 재생만 멈추고 컨트롤은 화면에 그대로 남아있는다(다시 누르면
  이어서 재생).
- 컨트롤을 닫는 버튼을 누르면 재생이 중단되고 컨트롤 전체가 화면에서 사라진다.

범위 제외:
- 오디오 생성, 오디오 파일 호스팅/저장은 이 기능의 범위에 포함되지 않는다 — 이미 완성된
  오디오 URL이 존재한다는 것을 전제로 한다.
- 텍스트를 음성으로 자동 변환하는 파이프라인은 다루지 않는다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 오디오로 게시글 청취하기 (Priority: P1)

내레이션 오디오가 준비된 게시글을 읽는 독자는 텍스트를 직접 읽는 대신 오디오로 내용을 들을 수 있다. 재생 버튼을 눌러 재생을 시작하고, 화면 하단에 나타난 컨트롤로 일시정지·탐색·배속 조절·종료를 자유롭게 할 수 있다.

**Why this priority**: 이 기능이 제공하는 핵심 가치 그 자체다. 이 시나리오 없이는 "오디오 내레이션 재생"이라는 기능이 성립하지 않는다.

**Independent Test**: 내레이션 오디오가 지정된 게시글 상세 페이지에서 재생 버튼을 눌러, 화면 하단에 재생 컨트롤이 나타나고 실제로 오디오가 재생되는지, 그리고 일시정지/재개, 진행 막대 탐색, 배속 변경, 닫기가 각각 의도대로 동작하는지 확인하는 것만으로 독립적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 내레이션 오디오가 지정된 게시글 상세 페이지, **When** 독자가 메타 정보 줄의 재생 버튼을 클릭, **Then** 화면 하단에 재생 컨트롤이 나타나고 오디오 재생이 시작된다.
2. **Given** 재생 컨트롤이 나타나 오디오가 재생되고 있는 상태, **When** 독자가 본문을 스크롤, **Then** 재생 컨트롤은 화면 하단에 계속 고정되어 보인다.
3. **Given** 오디오가 재생되고 있는 상태, **When** 독자가 일시정지 버튼을 클릭, **Then** 재생은 멈추지만 컨트롤은 화면에 그대로 남아있고, 같은 버튼을 다시 클릭하면 멈췄던 지점부터 재생이 이어진다.
4. **Given** 오디오가 재생되고 있는 상태, **When** 독자가 진행 막대의 다른 지점을 클릭 또는 드래그, **Then** 재생 위치가 그 지점으로 이동한다.
5. **Given** 재생 컨트롤이 열려 있는 상태, **When** 독자가 재생 속도를 변경, **Then** 이후 재생이 선택한 속도로 진행된다.
6. **Given** 재생 컨트롤이 열려 있는 상태(재생 중이든 일시정지 중이든), **When** 독자가 닫기 버튼을 클릭, **Then** 재생이 중단되고 컨트롤 전체가 화면에서 사라진다.

---

### User Story 2 - 게시글 단위로 오디오 제공 여부 결정하기 (Priority: P2)

저자는 게시글마다 내레이션 오디오 제공 여부를 개별적으로 정할 수 있다. 오디오를 지정한 게시글에만 재생 버튼이 나타나고, 지정하지 않은 게시글에는 재생과 관련된 어떤 UI도 노출되지 않는다.

**Why this priority**: 이 기능은 모든 게시글에 일괄 적용되는 것이 아니라 저자가 글마다 선택하는 부가 기능이어야 한다는 전제 조건이다. User Story 1의 재생 경험이 성립하려면 먼저 "이 글에 오디오가 있는가"가 정확히 구분되어야 하므로 P1 다음으로 중요하다.

**Independent Test**: 내레이션 오디오가 지정된 게시글과 지정되지 않은 게시글을 나란히 열어, 전자에서만 재생 버튼이 보이고 후자에서는 재생 관련 UI가 전혀 보이지 않는지 확인하는 것만으로 독립적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 저자가 내레이션 오디오를 지정한 게시글, **When** 독자가 해당 게시글 상세 페이지를 열람, **Then** 메타 정보 줄에 재생 버튼이 나타난다.
2. **Given** 저자가 내레이션 오디오를 지정하지 않은 게시글, **When** 독자가 해당 게시글 상세 페이지를 열람, **Then** 메타 정보 줄과 페이지 어디에도 재생 버튼 또는 재생 관련 UI가 나타나지 않는다.

---

### User Story 3 - 기존 메타 정보와 일관된 위치에 재생 버튼 배치 (Priority: P3)

재생 버튼은 게시글 상세 페이지의 기존 메타 정보(작성일, 수정일, 읽는 시간, 조회수, 썸네일 버튼)와 같은 줄에, 조회수 다음이자 썸네일 버튼보다 앞선 위치에 자연스럽게 자리한다.

**Why this priority**: 기능의 동작 자체에는 영향을 주지 않는 배치·일관성 요구사항이므로, 핵심 재생 경험(P1)과 노출 조건(P2)이 갖춰진 뒤에 마무리하면 되는 항목이다.

**Independent Test**: 내레이션 오디오와 썸네일이 모두 지정된 게시글의 메타 정보 줄을 확인해, 항목이 "조회수 → 재생 버튼 → 썸네일 버튼" 순서로 나열되는지 확인하는 것만으로 독립적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 내레이션 오디오와 썸네일이 모두 지정된 게시글, **When** 독자가 메타 정보 줄을 확인, **Then** 재생 버튼이 조회수 다음, 썸네일 버튼보다 앞에 나타난다.

---

### Edge Cases

- 지정된 오디오 URL을 불러올 수 없는 경우(파일 삭제, 잘못된 주소 등) 재생 버튼/컨트롤은 어떻게 동작해야 하는가?
- 독자가 재생 중에 다른 게시글이나 사이트 내 다른 페이지로 이동하면 재생과 컨트롤은 어떻게 되는가?
- 오디오가 끝까지 재생되어 종료된 뒤 컨트롤은 어떤 상태로 화면에 남는가?
- 좁은 모바일 화면에서 하단 고정 재생 컨트롤이 다른 화면 요소를 가리지는 않는가?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 게시글에 내레이션 오디오가 지정되어 있는 경우에만 해당 게시글 상세 페이지의 메타 정보 줄에 재생 버튼을 노출해야 한다.
- **FR-002**: 시스템은 내레이션 오디오가 지정되지 않은 게시글에서는 재생 버튼과 재생 관련 UI를 전혀 노출하지 않아야 한다.
- **FR-003**: 재생 버튼은 메타 정보 줄에서 조회수 항목 다음, 썸네일 버튼 항목보다 앞에 위치해야 한다.
- **FR-004**: 독자가 재생 버튼을 클릭하면 시스템은 뷰포트 하단에 고정된 재생 컨트롤을 표시하고 즉시 오디오 재생을 시작해야 한다.
- **FR-005**: 재생 컨트롤은 본문 스크롤 위치와 무관하게 화면에 계속 고정되어 보여야 한다.
- **FR-006**: 재생 컨트롤은 재생/일시정지 전환, 경과 재생 시간 표시, 전체 재생 시간 표시, 임의 지점으로 이동 가능한 진행 막대, 재생 속도 조절, 컨트롤을 닫는 동작을 제공해야 한다.
- **FR-007**: 일시정지 동작은 재생만 멈추고 재생 컨트롤은 화면에서 사라지지 않아야 하며, 이후 재생을 재개하면 멈춘 지점부터 이어져야 한다.
- **FR-008**: 닫기 동작은 재생을 중단시키고 재생 컨트롤 전체를 화면에서 제거해야 한다.
- **FR-009**: 독자는 진행 막대를 통해 재생 위치를 임의 지점으로 이동시킬 수 있어야 한다.
- **FR-010**: 독자는 재생 속도를 변경할 수 있어야 하며, 변경한 속도는 이후 재생에 즉시 반영되어야 한다.
- **FR-011**: 시스템은 오디오 파일을 자체적으로 생성하거나 저장/호스팅하지 않으며, 게시글에 지정된 오디오 위치를 그대로 재생 대상으로 사용해야 한다.
- **FR-012**: 같은 게시글 페이지에 머무는 동안 재생 컨트롤을 닫은 뒤 재생 버튼을 다시 누르면, 시스템은 닫기 직전에 듣던 위치부터 이어서 재생을 시작해야 한다. 단, 다른 게시글로 이동하거나 페이지를 새로고침하는 등 페이지를 벗어나면 이 위치는 유지되지 않으며, 이후 재생은 처음부터 시작된다.

### Key Entities

- **게시글 내레이션 오디오**: 게시글에 선택적으로 연결되는 오디오 자료. 재생 가능한 오디오의 위치(주소)를 값으로 가지며, 게시글당 최대 한 개까지 연결될 수 있다. 값이 없으면 해당 게시글은 오디오 재생 기능과 무관하게 동작한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 내레이션 오디오가 지정된 게시글에서 재생 버튼을 클릭하면 1초 이내에 오디오 재생이 시작된다.
- **SC-002**: 내레이션 오디오가 지정되지 않은 게시글에서는 어떤 열람 상황에서도 재생 버튼이 노출되는 비율이 0%다.
- **SC-003**: 독자는 별도의 설명 없이도 재생 컨트롤만으로 일시정지, 탐색, 배속 조절, 닫기를 스스로 수행할 수 있다.
- **SC-004**: 재생 중 본문을 끝까지 스크롤해도 재생 컨트롤은 100%의 시간 동안 화면에 계속 보인다.

## Assumptions

- 오디오 파일은 이미 웹 브라우저에서 바로 재생 가능한 형식과 위치(URL)로 준비되어 제공된다고 가정한다.
- 저자가 게시글에 내레이션 오디오를 등록하는 절차는 기존 썸네일 등록 절차와 동일한 방식(게시글 작성 시 값 지정)일 것으로 가정하며, 이를 위한 별도의 콘텐츠 입력 도구를 새로 만들 필요는 없다.
- 한 번에 하나의 게시글 상세 페이지만 열람 중인 상황을 기준으로 하며, 여러 게시글의 오디오를 동시에 재생하는 상황은 다루지 않는다.
- 재생 컨트롤이 열린 상태에서 다른 게시글이나 다른 페이지로 이동하면 재생은 중단되고 컨트롤도 함께 사라진다고 가정한다.
- 닫기로 사라진 재생 위치는 같은 페이지에 머무는 동안에만 기억되며(같은 글을 벗어나지 않고 다시 재생 버튼을 누르면 이어서 재생), 별도의 저장소(로컬 스토리지 등)에 영구 저장하지는 않는다고 가정한다.
- 오디오가 끝까지 재생되어도 컨트롤은 자동으로 닫히지 않고, 종료된 상태로 화면에 남아 독자가 직접 닫거나 다시 재생할 수 있다고 가정한다.
- 재생 속도로 제공할 구체적인 배속 값들(예: 1×, 1.25×, 1.5× 등)은 이후 설계 단계에서 정한다.
