# Quickstart: 게시글 오디오 내레이션 재생 검증

Constitution Principle I(Feature-Level Verification, NON-NEGOTIABLE)에 따라 `npm run build` +
`playwright-cli` 스킬로 실제 브라우저에서 검증한다. 이 프로젝트엔 자동화 테스트 프레임워크가
없으므로 아래가 유일한 검증 경로다.

## 사전 준비

이 저장소는 어떤 아티클에도 `audio:` frontmatter가 아직 없다. 검증을 위해 임시로 **한 개의
테스트용 아티클**에만 값을 채워 넣는다(브라우저에서 바로 재생 가능한 짧은 mp3 URL이면 충분 —
예: 실제 서비스에 올릴 파일이 아니어도 되고, 검증 후 되돌린다).

- **User Story 3(배치 순서) 검증까지 함께 하려면**: `thumbnail`이 이미 있는 아티클을 골라
  `audio`를 추가한다 — 예: `content/articles/14_spring_transaction.md` 상단 frontmatter에
  `audio: <재생 가능한 mp3 URL>` 한 줄을 추가.
- **오디오 없는 아티클(FR-002/User Story 2 대조군)**: `audio` 필드를 추가하지 않은 다른 아티클
  아무거나(예: 같은 디렉터리의 다른 글) 하나 그대로 둔다.

**⚠️ NON-NEGOTIABLE**: `content/articles/**`는 top-level `await loadArticles()`로 프로세스
시작 시 한 번만 읽힌다. frontmatter를 수정한 뒤 **반드시 `next dev`를 껐다 다시 켜거나
`npm run build`를 재실행**해야 변경이 반영된다 — 브라우저 새로고침만으로는 절대 보이지 않는다.

## 검증 절차

1. `npm run build` — 타입 에러/빌드 에러 없이 통과하는지 확인 (frontmatter/타입 확장이
   `thumbnail`과 동일한 형태로 들어갔는지의 1차 검증).
2. `playwright-cli`로 오디오를 지정한 아티클 상세 페이지(`/article/<slug>`)를 연다.
   - 메타 정보 줄에서 재생 버튼이 **조회수 다음, 썸네일 버튼보다 앞**에 나타나는지 확인
     (User Story 3 / FR-003).
3. 재생 버튼 클릭 → 뷰포트 하단에 플레이어가 나타나고 재생이 시작되는지 확인(User Story 1 /
   FR-004). 본문을 끝까지 스크롤해도 플레이어가 화면에 계속 고정돼 있는지 확인(FR-005).
4. 일시정지 버튼 클릭 → 재생만 멈추고 플레이어는 그대로 남아있는지, 다시 클릭하면 멈춘
   지점부터 이어지는지 확인(FR-007).
5. 진행 막대의 다른 지점을 클릭 → 그 위치로 재생이 이동하는지 확인(FR-009).
6. 배속 버튼을 눌러 값이 순환하는지, 순환된 배속으로 실제 재생 속도가 바뀌는지 확인
   (FR-010).
7. 닫기(X) 버튼 클릭 → 플레이어가 사라지고 재생이 멈추는지 확인(FR-008). 같은 페이지에서
   재생 버튼을 다시 클릭 → 닫기 직전 위치부터 이어서 재생되는지 확인(FR-012).
8. 다른 아티클로 이동(또는 새로고침) 후 원래 아티클로 돌아와 재생 버튼을 클릭 →
   처음부터 재생되는지 확인(FR-012 후단 / Assumptions).
9. `audio` 필드가 없는 아티클의 상세 페이지를 연다 → 메타 정보 줄 어디에도 재생 버튼이나
   재생 관련 UI가 없는지 확인(FR-001, FR-002, User Story 2).
10. 데스크탑 브레이크포인트와 모바일 브레이크포인트 양쪽에서 2~9를 한 번씩 훑어, 좁은
    화면에서 하단 플레이어가 다른 요소를 가리거나 잘리지 않는지 확인(Edge Cases).
11. 다크/라이트 테마 양쪽에서 재생 버튼·플레이어 스타일이 기존 메타 줄 아이콘들과 시각적으로
    맞는지 확인.

## 되돌리기

검증이 끝나면 1번에서 추가한 `audio:` 줄을 제거하고(실제로 오디오를 준비해 커밋할 게
아니라면), `next dev`를 다시 재시작해 원상태를 반영한다.
