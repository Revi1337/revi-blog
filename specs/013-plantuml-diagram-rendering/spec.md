# Feature Specification: PlantUML 다이어그램 렌더링

**Feature Branch**: `013-plantuml-diagram-rendering`

**Created**: 2026-08-15

**Status**: Draft

**Input**: User description: "PlantUML 다이어그램 렌더링 지원. 블로그 아티클 본문에서 ```plantuml 코드블록을 다이어그램 이미지로 렌더링한다. 앞서 구현된 Mermaid 다이어그램과 동일한 사용자 경험을 제공해야 한다. 요구사항: 1) 독자가 아티클을 읽을 때, ```plantuml 코드블록은 원본 텍스트가 아니라 렌더링된 다이어그램 이미지로 보인다. 2) 다이어그램 위에는 확대 버튼과 복사 버튼이 함께 노출된다. 확대 버튼 클릭 시, 다이어그램을 모달(팝업)로 크게 확대해서 볼 수 있다. 모달 안에서는 줌 인/아웃과 드래그 이동(팬)이 가능하다. 복사 버튼 클릭 시, 원본 PlantUML 소스 코드가 클립보드로 복사된다. 3) 이 두 버튼의 위치, 스타일, 인터랙션 방식은 Mermaid 다이어그램에 이미 적용된 것과 동일하게 통일되어야 한다 — 독자가 Mermaid 다이어그램인지 PlantUML 다이어그램인지 UI만으로는 구분할 수 없어야 한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 독자가 다이어그램을 그림으로 바로 본다 (Priority: P1)

독자가 PlantUML 문법(시퀀스 다이어그램, 클래스 다이어그램 등)이 포함된 아티클 페이지에 접속하면, 문법이 강조된 텍스트 코드 블록이 아니라 실제로 조판된 그림을 즉시 볼 수 있어야 한다. 그림을 보기 위해 클릭이나 별도 조작이 필요해서는 안 된다.

**Why this priority**: 이번 기능의 핵심 가치이며, 나머지(복사/확대) 기능은 이 렌더링이 존재해야 의미가 있다. 이것만으로도 Mermaid와 동등한 열람 경험이라는 목표를 달성한다.

**Independent Test**: PlantUML 코드펜스만 포함된 아티클을 발행해, 페이지 로드 즉시 그림이 렌더링되는지 확인하는 것으로 독립 검증 가능.

**Acceptance Scenarios**:

1. **Given** 본문에 유효한 PlantUML 시퀀스 다이어그램 문법이 있는 아티클, **When** 페이지를 렌더링하면, **Then** 원본 코드 텍스트가 아니라 조판된 다이어그램 그림이 표시된다.
2. **Given** 다크 모드와 라이트 모드, **When** 동일한 다이어그램을 각각 렌더링하면, **Then** 두 테마 모두에서 다이어그램 요소와 배경이 읽기 충분한 명도 대비로 표시된다.
3. **Given** 이번 변경 이전에 발행된, PlantUML 문법을 쓰지 않는 기존 아티클, **When** 페이지를 렌더링하면, **Then** 기존과 동일한 결과가 나온다(회귀 없음).

---

### User Story 2 - 독자가 다이어그램을 확대해서 자세히 본다 (Priority: P2)

독자가 렌더링된 다이어그램의 확대 버튼을 누르면, 이 블로그의 Mermaid 다이어그램 및 본문 이미지가 이미 제공하는 것과 동일한 방식의 확대 보기 창(모달)이 뜬다. 이 창에서 그림을 이동시키고, 확대/축소할 수 있어야 한다.

**Why this priority**: 다이어그램은 본문 폭에 맞춰 작게 그려질 수 있어, 복잡한 다이어그램일수록 세부 내용을 보기 위한 확대 열람이 독자 경험에 중요하다.

**Independent Test**: 렌더링된 다이어그램의 확대 버튼을 눌러 확대 보기 창이 뜨는지, 그 안에서 이동/확대·축소 조작이 각각 의도대로 동작하는지 확인하는 것으로 독립 검증 가능.

**Acceptance Scenarios**:

1. **Given** 렌더링된 다이어그램, **When** 확대 버튼을 클릭하면, **Then** 기존 Mermaid 다이어그램·이미지 라이트박스와 동일한 방식의 확대 보기 창이 뜬다.
2. **Given** 확대 보기 창이 열린 상태, **When** 드래그로 그림을 이동시키면, **Then** 그림이 드래그 방향으로 이동한다.
3. **Given** 확대 보기 창이 열린 상태, **When** 줌 인/아웃 조작을 하면, **Then** 그림이 각각 확대/축소된다.

---

### User Story 3 - 독자가 다이어그램의 원본 코드를 복사한다 (Priority: P3)

독자가 렌더링된 다이어그램의 복사 버튼을 누르면, 화면에 그려진 그림이 아니라 원본 PlantUML 코드 텍스트가 클립보드에 복사된다.

**Why this priority**: Mermaid 다이어그램과 동일하게 제공되어야 하는 부가 기능이지만, 핵심 열람 경험(그림으로 보기)이나 세부 확인(확대 보기)에 비해 사용 빈도가 낮을 것으로 예상되는 보조 기능이다.

**Independent Test**: 복사 버튼을 클릭한 뒤 클립보드 내용이 원본 PlantUML 코드 텍스트와 정확히 일치하는지 확인하는 것으로 독립 검증 가능.

**Acceptance Scenarios**:

1. **Given** 렌더링된 다이어그램, **When** 복사 버튼을 클릭하면, **Then** 클립보드에는 렌더링 이미지가 아니라 원본 PlantUML 코드 텍스트가 담긴다.

---

### Edge Cases

- PlantUML 문법에 오류(괄호 불일치 등)가 있으면 어떻게 되는가? → 페이지 전체 렌더링이 깨지지 않고, 오류가 발생한 자리에는 원본 코드가 그대로 표시된다.
- 다이어그램 렌더링을 완료할 수 없으면(예: 렌더링 실패) 어떻게 되는가? → 독자에게 명확한 실패 표시가 나타나고, 페이지의 다른 콘텐츠 열람에는 영향을 주지 않는다.
- 다이어그램이 본문 폭보다 넓게 그려지면 어떻게 되는가? → 레이아웃이 깨지지 않고 본문 폭에 맞게 표시된다.
- 독자가 Mermaid 다이어그램과 PlantUML 다이어그램을 함께 포함한 아티클을 볼 때 어떻게 되는가? → 두 종류 모두 동일한 확대/복사 버튼 위치·스타일·인터랙션으로 표시되어, 독자는 UI만으로 종류를 구분할 수 없다.
- 옵시디언 등 다른 저작 도구에서 작성한 원고를 그대로 옮겨온 경우는 어떻게 되는가? → 별도 수정 없이도 원고 작성자가 의도한 모습 그대로 렌더링된다.
- 이번 변경 이전에 발행된, PlantUML 문법을 쓰지 않는 아티클은 어떻게 되는가? → 기존 렌더링 결과가 달라지지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 ```plantuml 코드펜스를 문법 강조된 텍스트가 아니라 실제 다이어그램 이미지로 렌더링해야 한다.
- **FR-002**: 독자는 페이지 접속 즉시, 별도의 클릭이나 조작 없이 완성된 다이어그램을 볼 수 있어야 한다.
- **FR-003**: 시스템은 렌더링된 다이어그램마다 복사 버튼과 확대 버튼을 함께 표시해야 한다.
- **FR-004**: 시스템은 복사 버튼 클릭 시 렌더링된 이미지가 아니라 원본 PlantUML 코드 텍스트를 클립보드에 복사해야 한다.
- **FR-005**: 시스템은 확대 버튼 클릭 시 기존 Mermaid 다이어그램·이미지 라이트박스와 동일한 방식의 확대 보기 창을 띄워야 한다.
- **FR-006**: 확대 보기 창은 그림을 이동(팬)시키고 확대/축소(줌)할 수 있는 조작을 제공해야 한다.
- **FR-007**: 시스템은 확대 버튼과 복사 버튼의 위치, 스타일, 인터랙션 방식을 Mermaid 다이어그램과 동일하게 제공하여, 독자가 두 종류의 다이어그램을 UI만으로 구분할 수 없도록 해야 한다.
- **FR-008**: 시스템은 PlantUML 문법에 오류가 있어도 페이지 전체 렌더링이 실패하지 않아야 하며, 오류가 발생한 자리에는 원본 코드를 그대로 표시해야 한다.
- **FR-009**: 시스템은 다이어그램 렌더링을 완료할 수 없는 경우 독자에게 명확한 실패 표시를 제공하고, 페이지의 다른 콘텐츠 열람에 영향을 주지 않아야 한다.
- **FR-010**: 시스템은 다크 모드와 라이트 모드 각각에서 다이어그램이 읽기 충분한 명도 대비로 표시되도록 해야 한다.
- **FR-011**: 시스템은 이번 변경 이전에 발행된 아티클들의 렌더링 결과를 이번 변경으로 인해 달라지게 해서는 안 된다.
- **FR-012**: 시스템은 다이어그램이 본문 폭보다 넓은 경우에도 레이아웃이 깨지지 않도록 해야 한다.

### Key Entities

- **PlantUML 다이어그램 블록**: 본문 중 PlantUML 문법으로 작성된 하나의 다이어그램. 원본 코드, 렌더링된 이미지, 문법 오류/렌더링 실패 여부를 속성으로 가진다.
- **확대 보기 창**: 다이어그램을 크게 보기 위한 모달. Mermaid 다이어그램 및 본문 이미지의 확대 보기 창과 동일한 조작(이동, 확대/축소)을 공유한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: PlantUML 문법이 포함된 아티클에 접속하면 100%의 경우 별도 조작 없이 완성된 다이어그램을 즉시 볼 수 있다.
- **SC-002**: 복사 버튼 클릭 시 100%의 경우 클립보드 내용이 렌더링 이미지가 아니라 원본 다이어그램 코드와 정확히 일치한다.
- **SC-003**: 확대 보기 창에서 이동/확대·축소 조작이 100% 의도한 결과를 낸다.
- **SC-004**: Mermaid 다이어그램과 PlantUML 다이어그램의 확대·복사 버튼은 위치, 스타일, 인터랙션이 100% 동일하여 독자가 UI만으로 종류를 구분할 수 없다.
- **SC-005**: 문법 오류나 렌더링 실패가 있는 다이어그램이 포함된 페이지도 100% 정상적으로 로드되며, 페이지의 다른 콘텐츠 열람에 영향을 주지 않는다.
- **SC-006**: 다크/라이트 두 테마 각각에서 다이어그램이 시각적으로 구분 가능한 명도 대비를 유지한다.
- **SC-007**: 기존에 발행된 아티클들의 렌더링 결과가 이번 변경 적용 전후로 동일하다.

## Assumptions

- 지원 대상 다이어그램 문법은 표준 PlantUML 문법 범위로 가정하며, 실험적/비표준 확장 문법 지원은 이번 범위 밖으로 가정한다.
- 확대 보기 창과 복사 버튼의 위치·스타일·인터랙션은 기존 Mermaid 다이어그램 및 이미지 라이트박스 모달과 완전히 동일한 사용자 경험을 따르는 것으로 가정한다.
- 다이어그램 렌더링은 외부 렌더링 서비스에 의존할 수 있으며, 그 가용성 확보 방식(자체 호스팅 여부 등)은 이번 스펙의 범위가 아니라 기술 설계(plan) 단계에서 결정하는 것으로 가정한다.
- 문법 오류·렌더링 실패 시 대체 표시 방식은 이 프로젝트에 이미 있는 Mermaid 다이어그램의 오류 처리 관례(오류 위치에 원본 코드를 그대로 노출)를 따르는 것으로 가정한다.
- PlantUML 외 다른 다이어그램 포맷(Mermaid 제외, 예: Markmap, Excalidraw)은 이번 범위에서 명시적으로 제외한다.
