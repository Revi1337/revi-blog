# Feature Specification: 홈페이지 QuickSearch 태그 필터

**Feature Branch**: `006-quick-search-filter`

**Created**: 2026-07-21

**Status**: Draft

**Input**: User description: "홈페이지의 히어로 캐러셀 아래, 'Entry Stream' 섹션 헤더 위에 QuickSearch 버튼 그룹을 추가해야 해. 각 버튼은 미리 정의된 태그 조합(하나 이상의 태그를 묶은 프리셋)을 대표하고, 방문자가 버튼 하나를 클릭하면 새 화면으로 이동하거나 검색 모달을 여는 대신 바로 아래 'Entry Stream' 카드 그리드가 그 태그 조합을 모두 가진 아티클만으로 즉시 다시 그려져야 해. 이 매칭 규칙은 기존에 헤더의 Ctrl+K 검색 모달에서 `#태그` 형식으로 지원하는 다중 태그 AND 매칭(공백으로 구분한 여러 태그를 모두 만족하는 아티클만 보여주는 방식)과 동일해야 하지만, 검색 모달과는 완전히 독립된 별개의 상호작용이야. 버튼은 여러 개(대표적인 태그 조합별로 준비) 노출하고, 그중 하나가 활성화되면 시각적으로 선택된 상태임을 알 수 있어야 하며 동시에 두 개 이상은 활성화되지 않아. 현재 'Entry Stream' 헤더 우측의 'Filter: All'이라는 정적 텍스트는, 활성화된 QuickSearch 버튼의 이름(없으면 'All')을 실시간으로 보여주는 라벨로 바뀌어야 해. 이미 활성화된 버튼을 다시 클릭하거나 'All' 버튼을 클릭하면 필터가 해제되고 전체 아티클 목록으로 돌아가야 해. 필터링 결과가 하나도 없을 때는 그리드 영역에 결과가 없다는 안내 문구를 보여줘야 하고, 페이지네이션은 필터가 바뀔 때 최소한 1페이지로 리셋되어야 해(가능하면 필터링된 아티클 개수 기준으로 페이지 수도 다시 계산). 홈 화면 노출이 꺼진 아티클은 QuickSearch 필터 결과에도 나타나지 않아야 해. 버튼 그룹과 활성 상태 스타일은 dark/light 테마를 모두 그대로 따라야 하고, 모바일 화면에서도 버튼들이 잘리지 않고 스크롤되거나 줄바꿈되어 접근 가능해야 해. 구체적으로 어떤 태그 조합들을 몇 개 노출할지는 아직 정해지지 않았어 — 실제 아티클들의 태그 데이터를 참고해서 조합 후보를 제안하고, 필요하면 이 부분은 명확화 질문으로 확인해야 해."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 태그 조합 버튼으로 그리드 즉시 필터링하기 (Priority: P1)

방문자가 홈페이지 히어로 아래에 노출된 QuickSearch 버튼 중 하나를 클릭하면, 페이지 이동이나 검색 모달을 거치지 않고 바로 아래 'Entry Stream' 카드 그리드가 그 버튼이 대표하는 태그 조합을 모두 가진 아티클만으로 즉시 다시 그려진다.

**Why this priority**: 이 기능의 핵심 가치. 버튼 클릭이 그리드를 실제로 필터링하지 못하면 나머지 요구사항(해제, 라벨 갱신, 테마·모바일 대응)은 의미가 없다.

**Independent Test**: 서로 다른 태그를 가진 아티클이 섞여 있는 상태에서 QuickSearch 버튼 하나를 클릭했을 때, 해당 태그 조합을 모두 가진 아티클만 그리드에 남고 나머지는 사라지는지 확인하는 것만으로 완결적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 방문자가 홈페이지를 보고 있고 그리드에 전체 아티클이 노출되어 있음, **When** 특정 태그 조합을 대표하는 QuickSearch 버튼을 클릭함, **Then** 페이지 이동이나 모달 없이 그리드가 해당 태그 조합을 모두 가진 아티클만으로 즉시 갱신된다.
2. **Given** 그리드가 특정 QuickSearch 필터로 갱신되어 있음, **When** 갱신된 그리드의 아티클들을 확인함, **Then** 모두 해당 프리셋에 포함된 태그 전부를 가지고 있으며, 하나라도 누락된 아티클은 나타나지 않는다.
3. **Given** 어떤 QuickSearch 버튼도 활성화되지 않은 초기 상태임, **When** 홈페이지에 처음 진입함, **Then** 그리드에는 홈 화면 노출 대상 아티클 전체가 나타난다.

---

### User Story 2 - 필터 해제하고 전체 목록으로 되돌아가기 (Priority: P2)

방문자가 이미 활성화된 QuickSearch 버튼을 다시 클릭하거나 별도의 'All' 상태로 되돌리는 조작을 하면, 필터가 해제되고 그리드가 전체 아티클 목록으로 돌아간다.

**Why this priority**: 필터링(P1) 없이는 의미가 없지만, 필터를 되돌릴 방법이 없으면 방문자가 특정 태그 조합에 갇혀버리는 치명적인 사용성 문제가 생긴다.

**Independent Test**: QuickSearch 버튼으로 필터를 건 뒤, 같은 버튼을 다시 클릭(또는 'All' 조작)했을 때 그리드가 필터 이전의 전체 목록으로 돌아오는지 확인하는 것으로 완결적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 특정 QuickSearch 버튼이 활성화되어 그리드가 필터링되어 있음, **When** 방문자가 같은 버튼을 다시 클릭함, **Then** 필터가 해제되고 그리드가 전체 아티클 목록으로 돌아간다.
2. **Given** 특정 QuickSearch 버튼이 활성화되어 있음, **When** 방문자가 다른 QuickSearch 버튼을 클릭함, **Then** 이전 버튼은 비활성화되고 새로 클릭한 버튼만 활성화되며 그리드는 새 조합 기준으로 갱신된다(동시에 두 개 이상 활성화되지 않는다).

---

### User Story 3 - 필터 상태 라벨과 다크/라이트 테마 일관성 (Priority: P3)

방문자는 'Entry Stream' 헤더 우측의 라벨을 보고 현재 어떤 필터가 적용 중인지 항상 확인할 수 있으며, QuickSearch 버튼 그룹과 활성 상태 스타일은 현재 선택된 dark/light 테마를 그대로 따른다.

**Why this priority**: 필터링 동작(P1, P2) 자체에는 영향을 주지 않지만, 방문자가 지금 어떤 상태를 보고 있는지 인지하지 못하면 혼란을 준다. 이 프로젝트는 dark/light 쌍을 항상 함께 유지해야 하므로 별도로 검증할 가치가 있다.

**Independent Test**: QuickSearch 버튼을 활성화한 뒤 헤더의 필터 라벨이 해당 버튼 이름으로 바뀌는지, 필터를 해제하면 다시 'All'로 돌아오는지, 라이트/다크 테마 각각에서 버튼 그룹 스타일이 자연스러운지 확인하는 것으로 완결적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 어떤 QuickSearch 버튼도 활성화되지 않음, **When** 'Entry Stream' 헤더의 필터 라벨을 확인함, **Then** 'All'이 표시된다.
2. **Given** 특정 QuickSearch 버튼이 활성화됨, **When** 'Entry Stream' 헤더의 필터 라벨을 확인함, **Then** 활성화된 버튼의 이름이 실시간으로 표시된다.
3. **Given** 방문자가 라이트 테마 또는 다크 테마를 사용 중임, **When** QuickSearch 버튼 그룹과 활성 상태를 확인함, **Then** 둘 다 현재 테마의 색상 체계를 따른다.

---

### User Story 4 - 모바일에서 QuickSearch 버튼 사용하기 (Priority: P4)

방문자가 모바일 화면 너비로 홈페이지를 볼 때도 QuickSearch 버튼 그룹 전체에 접근할 수 있으며, 버튼이 화면 밖으로 잘리지 않는다.

**Why this priority**: 데스크톱에서의 핵심 필터링 동작(P1, P2)이 먼저 완성되어야 의미가 있는, 뷰포트별 레이아웃 대응 요구사항이다.

**Independent Test**: 모바일 뷰포트에서 QuickSearch 버튼 그룹이 스크롤 또는 줄바꿈을 통해 모든 버튼에 접근 가능한지, 버튼 클릭 시 데스크톱과 동일하게 그리드가 필터링되는지 확인하는 것으로 완결적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 방문자가 모바일 화면 너비로 홈페이지를 보고 있음, **When** QuickSearch 버튼 그룹 영역을 확인함, **Then** 버튼들이 잘리지 않고 스크롤되거나 줄바꿈되어 모두 접근 가능하다.
2. **Given** 모바일 화면임, **When** 방문자가 QuickSearch 버튼 하나를 탭함, **Then** 데스크톱과 동일하게 그리드가 즉시 필터링된다.

---

### Edge Cases

- 특정 QuickSearch 프리셋으로 필터링했을 때 조건을 만족하는 아티클이 하나도 없으면, 그리드 영역에 결과가 없음을 알리는 안내 문구가 표시된다.
- 필터가 변경되면(다른 프리셋 선택, 필터 해제 등) 페이지네이션은 최소한 1페이지로 리셋된다.
- 홈 화면 노출이 꺼진 아티클은 어떤 QuickSearch 프리셋을 선택해도 결과에 나타나지 않는다.
- 방문자가 이미 활성화된 버튼을 다시 클릭하는 것과 다른 버튼을 클릭하는 것은 서로 다른 결과(전자는 해제, 후자는 전환)를 낸다.
- 현재 콘텐츠는 아티클 수가 적고 태그가 아티클마다 대부분 고유하게 부여되어 있어, 일부 태그 조합 프리셋은 매치되는 아티클이 0~1개에 그칠 수 있다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 홈페이지의 히어로 캐러셀과 'Entry Stream' 섹션 헤더 사이에 QuickSearch 버튼 그룹을 노출해야 한다.
- **FR-002**: 각 QuickSearch 버튼은 하나 이상의 태그로 구성된 프리셋을 대표해야 한다.
- **FR-003**: 방문자가 QuickSearch 버튼을 클릭하면, 새 페이지로 이동하거나 검색 모달을 열지 않고 'Entry Stream' 카드 그리드가 해당 프리셋에 포함된 모든 태그를 가진 아티클만으로 즉시 다시 그려져야 한다.
- **FR-004**: 태그 매칭은 프리셋에 포함된 태그를 아티클이 전부 보유하고 있어야 매치로 간주하는 AND 방식이어야 하며, 헤더 검색 모달의 `#태그` 다중 태그 매칭 규칙과 동일해야 한다.
- **FR-005**: 한 번에 하나의 QuickSearch 버튼만 활성 상태일 수 있다.
- **FR-006**: 방문자가 이미 활성화된 버튼을 다시 클릭하면 필터가 해제되고 전체 아티클 목록으로 돌아가야 한다.
- **FR-007**: 시스템은 활성 필터를 해제하고 전체 목록으로 되돌리는 별도의 조작(예: 'All' 상태)을 제공해야 한다.
- **FR-008**: 'Entry Stream' 헤더의 필터 라벨은 현재 활성화된 QuickSearch 버튼의 이름을, 활성화된 버튼이 없으면 'All'을 실시간으로 표시해야 한다.
- **FR-009**: 필터링된 결과가 하나도 없을 때, 시스템은 그리드 영역에 결과가 없음을 알리는 안내 문구를 표시해야 한다.
- **FR-010**: 필터가 변경되면 페이지네이션은 최소한 1페이지로 리셋되어야 한다.
- **FR-011**: 시스템은 홈 화면 노출이 꺼진 아티클을 QuickSearch 필터 결과에서 제외해야 한다.
- **FR-012**: QuickSearch 버튼 그룹과 활성 상태 스타일은 방문자가 선택한 dark/light 테마를 그대로 따라야 한다.
- **FR-013**: 모바일 화면 너비에서도 QuickSearch 버튼 그룹은 잘리지 않고 스크롤되거나 줄바꿈되어 모든 버튼에 접근 가능해야 한다.
- **FR-014**: QuickSearch 필터는 헤더의 Ctrl+K 검색 모달과 독립적으로 동작해야 하며, 두 기능의 상태는 서로 영향을 주지 않아야 한다.
- **FR-015**: 시스템은 QuickSearch 프리셋 개수를 고정하지 않고 콘텐츠 증가에 따라 늘릴 수 있는 구조로 제공해야 하며, 초기 버전에서는 예시로 3개의 프리셋(각 1개에서 3개 사이의 태그로 구성된 조합)을 노출한다.

### Key Entities

- **QuickSearch 프리셋**: 하나 이상의 태그로 구성된 조합을 대표하는 버튼. 표시 이름(라벨)과 매칭에 사용되는 태그 목록을 가지며, 전체 프리셋 목록은 개수가 고정되지 않고 콘텐츠 증가에 따라 늘어날 수 있다(초기 버전은 예시로 3개).
- **아티클(필터 대상)**: 홈 카드 그리드에 노출되는 아티클. 태그 목록과 홈 화면 노출 여부를 가지며, 노출 여부가 꺼져 있으면 필터 결과에서 완전히 제외된다.
- **필터 상태**: 현재 활성화된 QuickSearch 프리셋(없으면 'All')을 나타내는 홈페이지 전역 상태로, 'Entry Stream' 헤더 라벨과 카드 그리드가 동시에 참조한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 방문자는 QuickSearch 버튼을 클릭한 즉시 페이지 이동이나 로딩 지연 없이 그리드가 갱신되는 것을 체감할 수 있다.
- **SC-002**: 활성화된 프리셋의 태그 조합을 전부 가지지 않은 아티클은 그리드에 100% 나타나지 않는다.
- **SC-003**: 방문자는 언제든 한 번의 조작(같은 버튼 재클릭 또는 'All')만으로 전체 아티클 목록으로 되돌아갈 수 있다.
- **SC-004**: 홈 화면 노출이 꺼진 아티클은 어떤 QuickSearch 프리셋을 선택하더라도 노출률 0%를 유지한다.
- **SC-005**: 모바일 방문자도 데스크톱과 동일한 QuickSearch 프리셋 전체에 스크롤 또는 줄바꿈을 통해 접근할 수 있다.
- **SC-006**: 매치되는 아티클이 없는 프리셋을 선택해도 빈 화면이 아니라 안내 문구가 노출된다.

## Assumptions

- 현재 콘텐츠는 7개 아티클이며 태그가 대부분 아티클마다 고유하게 부여되어 있어 조합이 거의 겹치지 않는다. 따라서 QuickSearch 프리셋은 콘텐츠 규모에 맞춰 적은 개수로 시작하고, 아티클이 늘어남에 따라 조합을 확장하는 것을 전제로 한다.
- QuickSearch 프리셋과 그 태그 구성은 사전에 정의된 목록이며, 방문자가 임의의 태그를 조합해 새 프리셋을 만드는 자유 조합 기능은 이번 범위에 포함하지 않는다. 다만 이 목록의 프리셋 개수는 고정값이 아니라, 콘텐츠가 늘어나면 관리자가 추가로 늘릴 수 있는 확장 가능한 구조여야 한다.
- 'All'은 별도의 선택 가능한 프리셋이 아니라 "활성화된 프리셋이 없는" 기본 상태를 나타낸다.
- 페이지네이션의 전체 페이지 수는 이상적으로 필터링된 아티클 개수를 기준으로 다시 계산되지만, 최소 요건은 필터가 바뀔 때 1페이지로 리셋되는 것이다.
- QuickSearch 필터는 이미 홈페이지에 로드되어 있는 아티클 목록(홈 화면 노출 대상) 안에서 동작하며, 별도의 서버 요청이나 페이지 새로고침 없이 즉시 반영된다.
- 검색 모달의 `#태그` 다중 태그 검색과 QuickSearch 필터는 태그 매칭 규칙(AND 매칭)만 공유할 뿐, 두 기능의 UI 상태와 상호작용은 서로 독립적이다.
- 초기 버전(예시) 3개 프리셋의 구체적인 태그 구성은 실제 콘텐츠의 태그 현황을 참고해 다음과 같이 제안한다(최종 확정 및 이후 추가 프리셋 구성은 구현 단계에서 조정 가능): (1) `GRPC` 단일 태그 — 2개 아티클과 매치, (2) `KAFKA`+`SPARK` 2개 태그 조합 — 1개 아티클과 매치, (3) `OAUTH2`+`SECURITY` 2개 태그 조합 — 1개 아티클과 매치. 이 중 2개 프리셋은 현재 콘텐츠 기준 매치 아티클이 1개뿐이며, 이는 Edge Cases에 명시된 "콘텐츠가 적어 조합이 거의 겹치지 않는" 현재 상태를 반영한 결과다. 콘텐츠가 늘어나면 이 초기 3개 외에 프리셋을 추가하는 것을 전제로 한다.
