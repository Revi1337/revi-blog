# Quickstart: 홈페이지 QuickSearch 태그 필터 검증

이 문서는 구현이 끝난 뒤 기능이 실제로 동작하는지 확인하는 절차다. 구현 코드나 테스트 코드 전체를
담지 않는다 — 세부 작업은 `tasks.md`(`/speckit-tasks`)에서 다룬다.

## 준비

```bash
npm install   # 신규 의존성 없음 — lockfile 변경 없어야 정상
npm run build
npm run dev   # http://localhost:3999
```

`npm run build`가 타입 에러 없이 끝나야 한다(특히 `BlogCardData.tags` 추가 이후 기존
`HeroCarousel`/`BlogCard` 소비처가 깨지지 않았는지가 여기서 드러난다).

## 시나리오 1 — 클릭 시 그리드 즉시 필터링 (spec US1)

1. 홈페이지(`/`)에 접속해 히어로 캐러셀 아래 QuickSearch 버튼 3개가 보이는지 확인한다.
2. 버튼 하나를 클릭한다.
3. **기대 결과**: 페이지 이동이나 모달 없이, 바로 아래 카드 그리드가 그 버튼의 태그 조합을 모두
   가진 아티클만으로 즉시 바뀐다. `playwright-cli`로 클릭 전/후 그리드에 남은 카드의 `slug`
   목록을 비교해 확인한다.

## 시나리오 2 — 필터 해제 (spec US2)

1. 시나리오 1 상태에서 방금 클릭한 버튼을 다시 클릭한다.
2. **기대 결과**: 그리드가 필터 이전 전체 아티클 목록으로 돌아온다.
3. 다른 QuickSearch 버튼으로 전환했을 때 이전 버튼이 비활성화되고 동시에 두 개 이상 활성화되지
   않는지도 함께 확인한다.

## 시나리오 3 — 필터 라벨 & 테마 일관성 (spec US3)

1. 어떤 버튼도 활성화하지 않은 초기 상태에서 'Entry Stream' 헤더 우측 라벨이 'All'인지 확인한다.
2. 버튼을 활성화하면 라벨이 해당 버튼 이름으로 바뀌는지 확인한다.
3. 라이트/다크 테마 각각에서 버튼 그룹과 활성 상태 스타일을 `claude-in-chrome`(또는 `playwright`
   MCP 스크린샷)으로 캡처해 두 테마 모두 자연스럽게 보이는지, 활성 버튼이 비활성 버튼과 시각적으로
   구분되는지 확인한다.

## 시나리오 4 — 모바일 뷰포트 (spec US4)

1. `playwright-cli`로 모바일 너비 뷰포트로 전환한다.
2. QuickSearch 버튼 그룹이 화면 밖으로 잘리지 않고 스크롤 또는 줄바꿈으로 전체 버튼에 접근 가능한지
   확인한다.
3. 버튼 탭 시 데스크톱과 동일하게 그리드가 필터링되는지 확인한다.

## 엣지 케이스 확인

- 매치되는 아티클이 없는 프리셋을 선택했을 때 그리드 영역에 안내 문구가 뜨는지 확인한다(현재
  콘텐츠 기준 `KAFKA`+`SPARK`, `OAUTH2`+`SECURITY` 프리셋은 매치 1개뿐이라, 실제 매치 0개
  시나리오는 프리셋 태그를 일시적으로 바꿔서라도 검증한다).
- 필터를 변경했을 때 페이지네이션이 1페이지로 리셋되는지 확인한다.
- `showOnHomepage: false`인 아티클(`content/articles/_syntax-preview.md`)이 어떤 QuickSearch
  프리셋을 선택해도 결과에 나타나지 않는지 확인한다.

## 정적 목업 동기화 확인 (Constitution Principle II)

- `core/home-dark.html`과 `core/home-light.html`을 나란히 열어 QuickSearch 버튼 그룹 마크업이
  실제 구현과 동일한 구조로 반영되어 있는지, 두 파일 사이에 스타일이 어긋나지 않는지 육안으로
  대조한다.

## 완료 기준

- 위 4개 시나리오와 엣지 케이스 전부가 실제 브라우저 구동으로 확인되어야 "완료"로 간주한다
  (Constitution Principle I — 코드 리뷰/타입체크만으로는 완료 처리하지 않는다).
