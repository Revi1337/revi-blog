# Feature Specification: 헤딩 접기/펼치기

**Feature Branch**: `015-heading-fold`

**Created**: 2026-09-03

**Status**: Draft

**Input**: User description: "아티클 본문의 헤딩(H1~H6)을 Obsidian 에디터처럼 접었다 펼 수 있는 기능을 추가한다. 현재 아티클 본문에는 헤딩을 접는 기능이 없다. 콜아웃(`> [!note]-` 같은 Obsidian 콜아웃 문법)에는 이미 접기/펼치기가 있지만, 이건 마크다운 작성자가 정한 콜아웃 블록 전용이고 헤딩 자체에는 적용되지 않는다. 이번 기능은 독자가 읽는 도중 임의의 헤딩을 직접 접었다 펼 수 있게 한다. 아티클 본문의 모든 헤딩(H1~H6)에 접기/펼치기 토글을 붙인다. 독자가 헤딩을 클릭(또는 헤딩 옆 토글 아이콘 클릭)하면 그 헤딩부터 다음에 나오는 같은 레벨 이상의 헤딩 직전까지의 모든 콘텐츠(하위 헤딩과 그 내용 포함)가 접힌다/펼쳐진다. 접힌 상태는 시각적으로 명확히 구분돼야 한다. 각 헤딩의 접힘 상태는 서로 독립적이다. 페이지를 새로 열 때 모든 헤딩은 항상 펼쳐진 기본 상태로 시작하고, 접힘 상태는 세션이나 브라우저에 저장되지 않는다(기존 콜아웃 접기와 동일한 원칙). 목차(TOC) 클릭, 앵커 링크 진입, 브라우저 뒤로가기/앞으로가기로 접힌 섹션 안 위치에 도달하면 자동으로 펼쳐져야 한다. 접힌 섹션 안에 어떤 종류의 콘텐츠(코드 블록, 이미지, 표, 콜아웃, 다이어그램 등)가 와도 정상 동작해야 한다. 토글은 키보드로도 조작 가능해야 하고 스크린 리더가 상태를 인지할 수 있어야 한다. 접힘 상태 영속화와 '모두 접기/펼치기' 일괄 조작은 이번 범위에서 제외한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 독자가 헤딩을 클릭해 콘텐츠를 접고 편다 (Priority: P1)

독자가 아티클을 읽는 도중 임의의 헤딩(H1~H6)을 클릭하면, 그 헤딩부터 다음에 나오는 같은 레벨 이상의 헤딩 직전까지의 모든 콘텐츠(하위 헤딩과 그 내용 포함)가 접히거나 펼쳐진다. **[amended, 사용자 피드백]** 별도의 화살표/쉐브론 아이콘은 두지 않는다 — 헤딩은 접기 기능이 없던 기존 화면과 시각적으로 완전히 동일해야 하고(폰트/여백/구분선 등 어떤 스타일도 달라지지 않음), 헤딩 텍스트 자체를 클릭하는 것이 곧 토글이다. 접힘 여부는 콘텐츠가 실제로 사라지고 나타나는 것 자체로만 드러난다.

**Why this priority**: 이번 기능의 핵심 가치이며, 나머지(자동 펼침, 접근성)는 이 토글 자체가 존재해야 의미가 있다.

**Independent Test**: 여러 헤딩 레벨이 섞인 아티클에서 각 헤딩을 조작해 접고 펼쳐지는지, 접힌 범위가 의도한 경계(다음 동급 이상 헤딩 직전)와 정확히 일치하는지 확인하는 것으로 독립 검증 가능.

**Acceptance Scenarios**:

1. **Given** 여러 단락과 하위 헤딩을 포함한 H2 섹션, **When** 그 H2 헤딩의 토글을 조작하면, **Then** H2부터 다음 H1/H2 헤딩 직전까지의 모든 콘텐츠(하위 H3 포함)가 접힌다.
2. **Given** 접힌 H2 섹션, **When** 같은 토글을 다시 조작하면, **Then** 콘텐츠가 펼쳐지고 접기 전과 동일한 모습으로 보인다.
3. **Given** 서로 다른 헤딩 두 개, **When** 하나만 접으면, **Then** 다른 헤딩의 펼침 상태는 영향받지 않고 그대로 유지된다.
4. **Given** 페이지를 새로 열거나 새로고침, **When** 페이지가 로드되면, **Then** 모든 헤딩이 항상 펼쳐진 기본 상태로 시작한다.

---

### User Story 2 - 독자가 목차/링크/뒤로가기로 이동한 위치가 접혀 있어도 내용을 볼 수 있다 (Priority: P2)

독자가 목차(TOC) 항목 클릭, 앵커 링크(#heading-id) 직접 진입, 브라우저 뒤로가기/앞으로가기로 특정 헤딩 위치에 도달했을 때, 그 헤딩이 접힌 섹션 안에 있다면 자동으로 펼쳐져서 목표 지점이 실제로 보여야 한다.

**Why this priority**: P1만으로는 독자가 어떤 섹션을 접어둔 채 TOC나 링크로 그 안의 하위 항목에 이동하면 스크롤만 되고 아무것도 안 보이는 상황이 생길 수 있다 — 기존 목차/딥링크 기능을 깨뜨리지 않기 위해 반드시 함께 갖춰야 하는 보완이다.

**Independent Test**: 특정 섹션을 접은 뒤, 그 섹션 하위 헤딩을 가리키는 목차 항목이나 앵커 링크로 이동해 자동으로 펼쳐지며 목표 위치가 화면에 보이는지 확인하는 것으로 독립 검증 가능.

**Acceptance Scenarios**:

1. **Given** 접힌 H2 섹션 안에 있는 H3 헤딩, **When** 그 H3을 가리키는 목차 항목을 클릭하면, **Then** 해당 H2 섹션이 자동으로 펼쳐지고 H3 위치로 스크롤된다.
2. **Given** 접힌 섹션 안 헤딩을 가리키는 앵커 링크(#heading-id)로 직접 진입, **When** 페이지가 로드되면, **Then** 그 섹션은 접힌 채가 아니라 자동으로 펼쳐진 상태로 표시된다.
3. **Given** 독자가 어떤 섹션을 접은 뒤 다른 페이지로 이동했다가 브라우저 뒤로가기로 복귀, **When** 복귀 시점의 이전 스크롤 위치가 접힌 섹션 안이었다면, **Then** 그 섹션이 자동으로 펼쳐져 콘텐츠가 보인다.

---

### User Story 3 - 키보드와 스크린 리더 사용자도 접기/펼치기를 이용할 수 있다 (Priority: P3)

키보드만으로 헤딩의 접기/펼치기 토글에 포커스를 옮기고 Enter/Space로 조작할 수 있어야 하며, 스크린 리더 사용자가 현재 펼침/접힘 상태를 인지할 수 있어야 한다.

**Why this priority**: 접근성은 중요하지만, 마우스/터치 조작이라는 핵심 상호작용(P1)과 내비게이션 무결성(P2)이 먼저 갖춰진 뒤에 추가돼도 독립적으로 검증·배포 가능한 계층이다.

**Independent Test**: 마우스 없이 키보드만으로 페이지의 모든 헤딩 토글에 접근해 조작할 수 있는지, 스크린 리더로 상태 변화가 공지되는지 확인하는 것으로 독립 검증 가능.

**Acceptance Scenarios**:

1. **Given** 페이지에 포커스가 있는 상태, **When** Tab 키로 헤딩 토글까지 포커스를 이동한 뒤 Enter 또는 Space를 누르면, **Then** 조작했을 때와 동일하게 콘텐츠가 접히거나 펼쳐진다.
2. **Given** 스크린 리더 사용자, **When** 헤딩 토글의 상태가 바뀌면, **Then** 스크린 리더가 현재 상태(펼침/접힘)를 읽어준다.

---

### Edge Cases

- 접힌 섹션 안에 다이어그램(Mermaid/PlantUML/Markmap), 이미지, 표, 코드 블록, 콜아웃이 있으면? → 펼쳤을 때 정상적으로 원래 모습 그대로 나타나야 하며, 접기/펼치기 자체가 이 콘텐츠들의 렌더링을 깨뜨리지 않아야 한다.
- 헤딩이 여러 단계로 중첩된 경우(H2 안에 H3, H3 안에 H4)? → 상위 헤딩을 접으면 하위 헤딩과 그 내용이 전부 함께 안 보이게 된다. 하위 헤딩 자체의 접힘/펼침 상태는 그대로 유지되어, 상위를 다시 펼쳤을 때 하위가 이전에 접혀 있었다면 여전히 접힌 채로 보인다.
- 브라우저 자체 페이지 내 검색(Ctrl+F/Cmd+F)으로 접힌 섹션 안의 텍스트를 찾으면? → 검색에 걸린 위치가 접힌 상태로 남아 안 보이는 일이 없어야 한다(이 블로그의 사이트 자체 검색 기능은 별도의 빌드타임 색인을 쓰므로 이 영향과는 무관).
- 다음에 나오는 동급 이상 헤딩이 없는, 문서 끝까지 이어지는 마지막 섹션? → 헤딩부터 문서 끝까지의 모든 콘텐츠가 접힘 대상이 된다.
- 헤딩 바로 다음에 콘텐츠 없이 곧바로 다음 헤딩이 나오는 빈 섹션? → 토글은 표시되지만 접어도 시각적으로 달라지는 내용이 없다.
- 이번 변경 이전에 발행된 기존 아티클은? → 별도 수정 없이 모든 기존 아티클에 동일하게 적용된다(콘텐츠 자체가 달라지는 게 아니라 열람 방식이 추가되는 것이므로 회귀 없음).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 아티클 본문의 모든 헤딩(H1~H6)에 접기/펼치기 토글을 제공해야 한다.
- **FR-002**: 독자가 헤딩의 토글을 조작하면, 그 헤딩부터 다음에 나오는 같은 레벨 이상의 헤딩 직전까지의 모든 콘텐츠(하위 헤딩과 그 내용 포함)가 접히거나 펼쳐져야 한다.
- **FR-003**: **[amended, 사용자 피드백]** 시스템은 헤딩을 클릭하는 것만으로 접기/펼치기가 토글되어야 하며, 접기 기능이 없던 기존 화면과 시각적으로 완전히 동일한 헤딩 스타일(폰트/여백/구분선 등)을 유지해야 한다 — 화살표/쉐브론 등 별도의 아이콘을 추가하지 않는다. 접힘/펼침 여부는 콘텐츠 자체가 사라지고 나타나는 것으로만 드러난다.
- **FR-004**: 각 헤딩의 접힘/펼침 상태는 서로 독립적으로 유지되어야 한다 — 한 헤딩을 조작해도 다른 헤딩 자체의 상태 값은 바뀌지 않는다.
- **FR-005**: 시스템은 페이지가 새로 로드될 때마다(최초 접속, 새로고침, 다른 글에서 이동) 모든 헤딩을 펼쳐진 기본 상태로 표시해야 한다. 접힘 상태는 세션이나 브라우저에 저장되지 않는다.
- **FR-006**: 목차(TOC) 항목 클릭, 앵커 링크 직접 진입, 브라우저 뒤로가기/앞으로가기로 특정 헤딩 위치에 도달했을 때, 그 헤딩이 접힌 섹션 안에 있으면 시스템은 해당 섹션을 자동으로 펼쳐 목표 지점이 보이도록 해야 한다.
- **FR-007**: 시스템은 접힌 섹션 안의 어떤 콘텐츠 종류(본문 텍스트, 코드 블록, 이미지, 표, 콜아웃, 다이어그램 등)에 대해서도 접기/펼치기가 정상 동작하도록 해야 하며, 펼쳤을 때 콘텐츠가 원래 모습 그대로 나타나야 한다.
- **FR-008**: 접기/펼치기 토글은 키보드로 포커스를 이동해 Enter 또는 Space로 조작할 수 있어야 한다.
- **FR-009**: 시스템은 스크린 리더 사용자가 각 토글의 현재 펼침/접힘 상태를 인지할 수 있도록 해야 한다.
- **FR-010**: 브라우저 자체 페이지 내 검색으로 찾은 텍스트가 접힌 섹션 안에 있으면, 시스템은 그 텍스트가 검색 결과로 확인되지 않는 상태로 남지 않도록 해야 한다.
- **FR-011**: 시스템은 헤딩 접기/펼치기 동작이 기존 목차 스크롤 위치 추적 등 다른 페이지 기능을 깨뜨리지 않도록 해야 한다.
- **FR-012**: 시스템은 이번 변경 이전에 발행된 기존 아티클들의 열람 경험(콘텐츠 자체)을 이번 변경으로 인해 저해하지 않아야 한다 — 모든 기존 아티클에 동일하게 접기/펼치기가 추가된다.

### Key Entities

- **헤딩 섹션**: 아티클 본문의 한 헤딩(H1~H6)과, 그 헤딩부터 다음에 나오는 동급 이상 헤딩 직전까지의 콘텐츠 범위. 접힘/펼침 상태를 속성으로 가지며, 이 상태는 현재 페이지 인스턴스 동안만 유지되고 영속되지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 아티클 본문의 모든 헤딩(H1~H6)에서 100% 접기/펼치기 토글이 동작한다.
- **SC-002**: 헤딩을 접으면 100%의 경우 그 헤딩부터 다음 동급 이상 헤딩 직전까지의 콘텐츠(하위 헤딩 포함)만 정확히 숨겨지고, 그 외 콘텐츠는 영향받지 않는다.
- **SC-003**: 목차 항목 클릭, 앵커 링크 진입, 브라우저 뒤로/앞으로가기로 접힌 섹션 안 위치에 도달했을 때 100% 자동으로 펼쳐져 목표 지점이 보인다.
- **SC-004**: 페이지를 새로 열거나 새로고침했을 때 100% 모든 헤딩이 펼쳐진 기본 상태로 시작한다.
- **SC-005**: 접힌 섹션 안에 다이어그램(Mermaid/PlantUML/Markmap)이 있는 아티클에서, 펼쳤을 때 100% 다이어그램이 온전한 모습으로 정상 표시된다(깨짐이나 빈 화면 없음).
- **SC-006**: 키보드만으로 100% 모든 헤딩 토글에 접근하고 조작할 수 있다.
- **SC-007**: 이번 변경 이전에 발행된 아티클 전체에서 콘텐츠 자체의 렌더링 결과가 이번 변경 적용 전후로 동일하다.

## Assumptions

- **[amended, 사용자 피드백으로 확정]** 접기/펼치기 토글의 조작 트리거 영역은 헤딩 텍스트 전체다(전용 아이콘 없음) — 헤딩 클릭 = 토글. 텍스트 드래그 선택/복사는 클릭(누르고 바로 뗌)과 드래그(누른 채 이동)가 구분되는 브라우저 기본 동작이라 충돌하지 않는다.
- 접기/펼치기 상태는 이 프로젝트의 기존 콜아웃 접기 기능과 동일한 원칙으로, 세션/브라우저에 영속화하지 않는 것으로 가정한다(FR-005).
- "모두 접기/모두 펼치기" 같은 일괄 조작 버튼은 이번 범위에서 제외하는 것으로 가정한다.
- 이 블로그의 사이트 자체 검색(빌드타임 색인 기반)은 헤딩 접기 상태와 무관하게 기존과 동일하게 동작하는 것으로 가정한다.
- 헤딩 접기는 아티클 상세 페이지 본문에만 적용되고, 홈 화면의 글 목록 미리보기 등 다른 화면에는 영향을 주지 않는 것으로 가정한다.
