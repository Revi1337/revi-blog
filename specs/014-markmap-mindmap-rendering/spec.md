# Feature Specification: Markmap 마인드맵 렌더링

**Feature Branch**: `014-markmap-mindmap-rendering`

**Created**: 2026-08-15

**Status**: Draft

**Input**: User description: "블로그 아티클 콘텐츠 파이프라인에 Markmap 마인드맵을 아티클 본문에서 시각적으로 렌더링하는 기능을 추가한다. 현재는 ```markmap 코드펜스를 써도 문법이 강조된 텍스트 코드 블록으로만 보일 뿐, 실제 마인드맵 그림으로 표시되지 않는다. 이 블로그는 이미 Mermaid와 PlantUML 다이어그램을 코드펜스만 작성하면 자동으로 그림으로 렌더링해주는데, 마인드맵 구조의 콘텐츠(주제-하위주제 트리)를 작성하는 저자와 그걸 읽는 독자에게도 동일한 수준의 경험을 제공해야 한다. 저자는 옵시디언 등에서 작성한 마인드맵 원고를 그대로 옮겨와도 깨지지 않고 의도한 트리 구조 그대로 나타나길 기대하고, 독자는 페이지 접속 즉시 완성된 마인드맵을 볼 수 있어야 하며 그림을 보기 위해 별도의 클릭/조작이 필수여서는 안 된다. 렌더링된 마인드맵은 이 블로그의 다른 모든 코드 블록/다이어그램과 동일하게, 타이틀바와 트래픽라이트 점 3개가 있는 macOS 창 스타일 컨테이너 안에 표시되어야 한다. 별도의 카드나 프레임으로 다시 감싸 '프레임 안에 사진이 하나 더 얹힌' 것처럼 보여서는 안 되고, Mermaid/PlantUML 다이어그램과 시각적으로 통일된 느낌이어야 한다. Markmap 마인드맵은 기존 Mermaid 다이어그램과 달리 그 자체로 인터랙티브한 게 핵심 가치다 — 독자가 본문에 렌더링된 마인드맵에서 곧바로 가지를 접고 펼치거나, 확대/축소하고, 화면을 이동시키며 원하는 부분을 탐색할 수 있어야 한다. 이 인터랙션은 확대 보기 창을 따로 열지 않고도 본문에 렌더링된 상태 그대로 가능해야 한다. 마인드맵 문법이나 구조에 오류가 있어도 페이지 전체 렌더링이 깨지면 안 되고, 다크/라이트 테마 전환 시에도 마인드맵이 읽기 가능한 상태를 유지해야 한다. 기존에 발행된 아티클들의 렌더링 결과는 이번 변경으로 달라지지 않아야 한다. 렌더링된 마인드맵에는 기존 Mermaid/PlantUML 다이어그램과 동일하게 복사 버튼과 확대 버튼 두 개가 함께 표시되어야 한다. 복사 버튼을 누르면 화면에 그려진 그림이 아니라 원본 Markmap 코드 텍스트가 클립보드에 복사되어야 한다. 확대 버튼을 누르면, 이 블로그가 본문 이미지를 클릭했을 때 이미 보여주고 있는 라이트박스 모달과 동일한 방식의 확대 보기 창이 떠야 한다. 이 확대 보기 창에서도 기존 Mermaid/PlantUML 확대 보기와 완전히 동일하게, 마우스로 화면을 직접 드래그해서 이동시킬 수 있어야 하고, 상하좌우 화살표 버튼, 이동/확대 상태를 원래대로 되돌리는 리셋 버튼, 돋보기 +/- 확대·축소 버튼도 그대로 제공되어야 하며, 이 안에서도 마인드맵의 가지를 접고 펼칠 수 있어야 한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 독자가 마인드맵을 그림으로 바로 본다 (Priority: P1)

독자가 Markmap 문법(주제-하위주제 트리 구조)이 포함된 아티클 페이지에 접속하면, 문법이 강조된 텍스트 코드 블록이 아니라 실제로 조판된 마인드맵 그림을 즉시 볼 수 있어야 한다. 그림을 보기 위해 클릭이나 별도 조작이 필요해서는 안 되며, 렌더링된 마인드맵은 이 블로그의 다른 코드 블록/다이어그램과 동일한 macOS 창 스타일(타이틀바 + 트래픽라이트 점 3개) 컨테이너 안에 표시되어야 한다.

**Why this priority**: 이번 기능의 핵심 가치이며, 나머지(인라인 조작/확대/복사) 기능은 이 렌더링이 존재해야 의미가 있다. 이것만으로도 Mermaid/PlantUML과 동등한 열람 경험이라는 목표를 달성한다.

**Independent Test**: Markmap 코드펜스만 포함된 아티클을 발행해, 페이지 로드 즉시 그림이 다른 다이어그램과 동일한 컨테이너 스타일로 렌더링되는지 확인하는 것으로 독립 검증 가능.

**Acceptance Scenarios**:

1. **Given** 본문에 유효한 Markmap 문법이 있는 아티클, **When** 페이지를 렌더링하면, **Then** 원본 코드 텍스트가 아니라 조판된 마인드맵 그림이 표시된다.
2. **Given** 렌더링된 마인드맵, **When** 화면에 표시되면, **Then** 이 블로그의 다른 코드 블록/다이어그램과 동일한 타이틀바 + 트래픽라이트 컨테이너 안에 표시되고, 별도의 카드나 프레임으로 다시 감싸지지 않는다.
3. **Given** 다크 모드와 라이트 모드, **When** 동일한 마인드맵을 각각 렌더링하면, **Then** 두 테마 모두에서 마인드맵 요소와 배경이 읽기 충분한 명도 대비로 표시된다.
4. **Given** 이번 변경 이전에 발행된, Markmap 문법을 쓰지 않는 기존 아티클, **When** 페이지를 렌더링하면, **Then** 기존과 동일한 결과가 나온다(회귀 없음).

---

### User Story 2 - 독자가 본문에서 곧바로 마인드맵의 가지를 접고 펼친다 (Priority: P2)

독자가 확대 보기 창을 따로 열지 않고도, 본문에 렌더링된 마인드맵에서 곧바로 가지를 클릭해 접고 펼칠 수 있어야 한다.

**Why this priority**: 정적 그림으로만 보이는 Mermaid 다이어그램과 달리, 인라인 인터랙션은 Markmap이 제공해야 하는 핵심 차별 가치로 명시되었다. 이게 없으면 Markmap을 Mermaid mindmap과 구분할 이유가 사라진다.

> **[amended]** 최초 버전은 이 인라인 인터랙션에 확대/축소·화면 이동(팬)도 포함했으나, 실제 사용
> 중 발견된 문제로 범위를 접기/펼치기만으로 좁혔다 — Mermaid/PlantUML의 macOS 프리뷰는 완전히
> 정적인데 Markmap만 인라인에서 뷰(위치/배율)가 바뀔 수 있으면, (1) 확대 보기 창에만 있는
> "원래대로" 리셋 버튼이 인라인에도 필요해지고, (2) 다른 두 다이어그램과의 시각적 일관성이
> 깨진다. 또한 인라인 팬/줌이 트랙패드 스크롤·마우스 휠 이벤트를 가로채, 독자가 글을 읽으며
> 스크롤하다가 커서가 마인드맵 위를 지나가는 순간 페이지 스크롤이 멈추고 다이어그램이 대신
> 조작되는 회귀가 실측으로 확인됐다(FR-002 취지 위배). 확대/축소·화면 이동은 User Story 3(확대
> 보기 창)에서만 제공하는 것으로 결정했다 — 접기/펼치기는 뷰 상태를 바꾸지 않아(같은 노드를
> 다시 클릭하면 바로 복구됨) 리셋 버튼 없이도 "실수로 망가뜨릴" 위험이 없다는 점이 이 결정의
> 핵심 근거다.

**Independent Test**: Markmap이 렌더링된 아티클에서 확대 보기 창을 열지 않은 채로 가지 접기/펼치기를 시도해 의도대로 동작하는지, 그리고 드래그/휠 조작이 더는 다이어그램에 반응하지 않고 페이지 스크롤이 정상 동작하는지 확인하는 것으로 독립 검증 가능.

**Acceptance Scenarios**:

1. **Given** 본문에 렌더링된 마인드맵, **When** 특정 가지를 클릭해 접거나 펼치면, **Then** 확대 보기 창을 열지 않은 상태에서도 해당 가지가 접히거나 펼쳐진다.
2. **Given** 본문에 렌더링된 마인드맵, **When** 마인드맵 위에서 마우스 드래그나 휠 스크롤을 시도하면, **Then** 다이어그램은 반응하지 않고 페이지가 평소처럼 스크롤된다.

### User Story 3 - 독자가 마인드맵을 확대해서 자세히 본다 (Priority: P3)

독자가 렌더링된 마인드맵의 확대 버튼을 누르면, 이 블로그가 본문 이미지·Mermaid·PlantUML 다이어그램에서 이미 제공하는 것과 동일한 방식의 확대 보기 창이 뜬다. 이 창에서 마우스 드래그로 화면을 이동시키거나, 상하좌우 화살표 버튼으로 이동시키거나, 돋보기 +/- 버튼으로 확대/축소하거나, 리셋 버튼으로 이동/확대 상태를 원래대로 되돌릴 수 있어야 하며, 이 안에서도 마인드맵의 가지를 접고 펼칠 수 있어야 한다.

**Why this priority**: 마인드맵은 본문 폭에 맞춰 작게 그려질 수 있어, 복잡한 마인드맵일수록 세부 내용을 보기 위한 확대 열람이 독자 경험에 중요하다. 다만 인라인 조작(User Story 2)이 이미 기본적인 탐색을 제공하므로, 확대 보기는 그보다 낮은 우선순위다.

**Independent Test**: 렌더링된 마인드맵의 확대 버튼을 눌러 확대 보기 창이 뜨는지, 그 안에서 드래그 이동/화살표 이동/리셋/확대·축소/가지 접기·펼치기 조작이 각각 의도대로 동작하는지 확인하는 것으로 독립 검증 가능.

**Acceptance Scenarios**:

1. **Given** 렌더링된 마인드맵, **When** 확대 버튼을 클릭하면, **Then** 기존 이미지·Mermaid·PlantUML 라이트박스와 동일한 방식의 확대 보기 창이 뜬다.
2. **Given** 확대 보기 창이 열린 상태, **When** 마우스로 화면을 드래그하면, **Then** 그림이 드래그 방향으로 이동한다.
3. **Given** 확대 보기 창이 열린 상태, **When** 상하좌우 화살표 버튼을 클릭하면, **Then** 그림이 해당 방향으로 이동한다.
4. **Given** 확대 보기 창에서 이동/확대를 조작한 상태, **When** 리셋 버튼을 클릭하면, **Then** 이동 위치와 확대 배율이 모두 최초 상태로 되돌아간다.
5. **Given** 확대 보기 창이 열린 상태, **When** 돋보기 +/- 버튼을 클릭하면, **Then** 그림이 각각 확대/축소된다.
6. **Given** 확대 보기 창이 열린 상태, **When** 특정 가지를 클릭해 접거나 펼치면, **Then** 해당 가지가 접히거나 펼쳐진다.

---

### User Story 4 - 독자가 마인드맵의 원본 코드를 복사한다 (Priority: P4)

독자가 렌더링된 마인드맵의 복사 버튼을 누르면, 화면에 그려진 그림이 아니라 원본 Markmap 코드 텍스트가 클립보드에 복사된다.

**Why this priority**: Mermaid/PlantUML 다이어그램과 동일하게 제공되어야 하는 부가 기능이지만, 핵심 열람 경험(그림으로 보기)이나 인라인/확대 탐색에 비해 사용 빈도가 낮을 것으로 예상되는 보조 기능이다.

**Independent Test**: 복사 버튼을 클릭한 뒤 클립보드 내용이 원본 Markmap 코드 텍스트와 정확히 일치하는지 확인하는 것으로 독립 검증 가능.

**Acceptance Scenarios**:

1. **Given** 렌더링된 마인드맵, **When** 복사 버튼을 클릭하면, **Then** 클립보드에는 렌더링 이미지가 아니라 원본 Markmap 코드 텍스트가 담긴다.

---

### Edge Cases

- Markmap 문법이나 구조에 오류가 있으면 어떻게 되는가? → 페이지 전체 렌더링이 깨지지 않고, 오류가 발생한 자리에는 원본 코드가 그대로 표시된다.
- 마인드맵이 본문 폭보다 넓거나 깊은 트리로 그려지면 어떻게 되는가? → 레이아웃이 깨지지 않고 본문 폭 안에서 잘려 보인다(인라인에서는 확대/이동으로 탐색할 수 없다 — 전체를 보려면 확대 보기 창을 연다).
- 옵시디언 등 다른 저작 도구에서 작성한 마인드맵 원고를 그대로 옮겨온 경우는 어떻게 되는가? → 별도 수정 없이도 원고 작성자가 의도한 트리 구조 그대로 렌더링된다.
- 독자가 Mermaid·PlantUML·Markmap을 함께 포함한 아티클을 볼 때 어떻게 되는가? → 세 종류 모두 동일한 macOS 컨테이너, 확대/복사 버튼 위치·스타일·인터랙션으로 표시되어, 독자는 UI만으로 종류를 구분할 수 없다. 인라인 인터랙션(가지 접기/펼치기만 가능, 드래그/휠은 셋 다 무반응)도 동일하다.
- 독자가 마인드맵 위에서 스크롤하면 어떻게 되는가? → 다이어그램이 아니라 페이지가 정상적으로 스크롤된다(인라인 드래그/휠 비활성화, [amended] User Story 2 참고).
- 독자가 본문에서 가지를 접은 뒤 페이지를 벗어나거나 새로고침하면 어떻게 되는가? → 접힘 상태는 저장되지 않고, 다시 접속하면 최초 렌더링 상태(전체 펼침)로 돌아간다.
- 이번 변경 이전에 발행된, Markmap 문법을 쓰지 않는 아티클은 어떻게 되는가? → 기존 렌더링 결과가 달라지지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 ```markmap 코드펜스를 문법 강조된 텍스트가 아니라 실제 마인드맵 그림으로 렌더링해야 한다.
- **FR-002**: 독자는 페이지 접속 즉시, 별도의 클릭이나 조작 없이 완성된 마인드맵을 볼 수 있어야 한다.
- **FR-003**: 시스템은 렌더링된 마인드맵을 이 블로그의 다른 코드 블록/다이어그램과 동일한 macOS 창 스타일(타이틀바 + 트래픽라이트 점 3개) 컨테이너 안에 표시해야 하며, 별도의 카드나 프레임으로 다시 감싸서는 안 된다.
- **FR-004**: 독자는 확대 보기 창을 열지 않고도 본문에 렌더링된 마인드맵에서 곧바로 가지를 접고 펼칠 수 있어야 한다.
- **FR-005**: 시스템은 본문 인라인 마인드맵에서 드래그(팬)와 휠 스크롤(줌)을 비활성화해야 한다 — 마우스 드래그나 휠 스크롤은 다이어그램에 반응하지 않고 페이지 스크롤 등 기본 동작으로 그대로 전달되어야 한다. 확대/축소·화면 이동은 확대 보기 창(FR-009)에서만 제공한다. **[amended]** 최초 요구사항은 반대(인라인에서도 확대/축소·이동 가능)였으나, Mermaid/PlantUML과의 일관성 부족 및 페이지 스크롤 하이재킹 문제가 실사용 중 발견되어 정반대로 변경됨(User Story 2 참고).
- **FR-006**: 시스템은 렌더링된 마인드맵마다 복사 버튼과 확대 버튼을 함께 표시해야 한다.
- **FR-007**: 시스템은 복사 버튼 클릭 시 렌더링된 그림이 아니라 원본 Markmap 코드 텍스트를 클립보드에 복사해야 한다.
- **FR-008**: 시스템은 확대 버튼 클릭 시 기존 이미지·Mermaid·PlantUML 라이트박스와 동일한 방식의 확대 보기 창을 띄워야 한다.
- **FR-009**: 확대 보기 창은 마우스 드래그로 화면을 이동시키는 조작, 상하좌우 화살표 버튼, 이동/확대 상태를 최초 상태로 되돌리는 리셋 버튼, 돋보기 +/- 확대·축소 버튼을 제공해야 한다.
- **FR-010**: 확대 보기 창 안에서도 독자는 마인드맵의 가지를 접고 펼칠 수 있어야 한다.
- **FR-011**: 시스템은 확대 버튼과 복사 버튼의 위치, 스타일, 인터랙션 방식을 기존 Mermaid/PlantUML 다이어그램과 동일하게 제공하여, 독자가 세 종류의 다이어그램을 UI만으로 구분할 수 없도록 해야 한다.
- **FR-012**: 시스템은 Markmap 문법이나 구조에 오류가 있어도 페이지 전체 렌더링이 실패하지 않아야 하며, 오류가 발생한 자리에는 원본 코드를 그대로 표시해야 한다.
- **FR-013**: 시스템은 다크 모드와 라이트 모드 각각에서 마인드맵이 읽기 충분한 명도 대비로 표시되도록 해야 한다.
- **FR-014**: 시스템은 이번 변경 이전에 발행된 아티클들의 렌더링 결과를 이번 변경으로 인해 달라지게 해서는 안 된다.
- **FR-015**: 시스템은 마인드맵이 본문 폭보다 넓은 경우에도 레이아웃이 깨지지 않도록 해야 한다.

### Key Entities

- **Markmap 마인드맵 블록**: 본문 중 Markmap 문법으로 작성된 하나의 마인드맵. 원본 코드, 렌더링된 그림, 가지 접힘/펼침 상태, 문법 오류 여부를 속성으로 가진다. 이동 위치/확대 배율은 상태로 갖지 않는다(인라인에서는 조작 불가, FR-005).
- **확대 보기 창**: 마인드맵을 크게 보기 위한 모달. 이동 위치와 확대 배율을 상태로 가지며, 리셋 시 두 값 모두 초기 상태로 돌아간다. 가지 접힘/펼침도 자체적으로 가지지만(FR-010), 본문과 공유하지 않고 항상 전체 펼침으로 새로 시작한다(Assumptions).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Markmap 문법이 포함된 아티클에 접속하면 100%의 경우 별도 조작 없이 완성된 마인드맵을 즉시 볼 수 있다.
- **SC-002**: 렌더링된 마인드맵은 100%의 경우 다른 코드 블록/다이어그램과 동일한 시각적 컨테이너(타이틀바 + 트래픽라이트) 안에 표시된다.
- **SC-003**: 독자는 확대 보기 창을 열지 않고도 100% 본문에서 곧바로 마인드맵의 가지 접기/펼치기를 할 수 있으며, 드래그·휠 스크롤은 100% 다이어그램에 반응하지 않고 페이지 기본 동작(스크롤)으로 전달된다. **[amended]**
- **SC-004**: 복사 버튼 클릭 시 100%의 경우 클립보드 내용이 렌더링 이미지가 아니라 원본 마인드맵 코드와 정확히 일치한다.
- **SC-005**: 확대 보기 창의 드래그 이동·화살표 이동·리셋·확대/축소·가지 접기/펼치기 조작 각각이 100% 의도한 결과를 낸다.
- **SC-006**: Mermaid·PlantUML·Markmap 세 종류 다이어그램의 확대·복사 버튼은 위치, 스타일, 인터랙션이 100% 동일하여 독자가 UI만으로 종류를 구분할 수 없다.
- **SC-007**: 문법/구조 오류가 있는 마인드맵이 포함된 페이지도 100% 정상적으로 로드되며, 페이지의 다른 콘텐츠 열람에 영향을 주지 않는다.
- **SC-008**: 다크/라이트 두 테마 각각에서 마인드맵이 시각적으로 구분 가능한 명도 대비를 유지한다.
- **SC-009**: 기존에 발행된 아티클들의 렌더링 결과가 이번 변경 적용 전후로 동일하다.

## Assumptions

- 지원 대상 마인드맵 구조는 표준 마크다운 아웃라인(헤딩/리스트 계층)을 트리로 변환하는 범위로 가정하며, 실험적/비표준 확장 문법 지원은 이번 범위 밖으로 가정한다.
- 본문에 렌더링된 마인드맵의 초기 가지 펼침 상태는 전체 펼침을 기본값으로 가정한다.
- 독자가 본문 또는 확대 보기 창에서 조작한 접기/펼치기(및 확대 보기 창의 이동·확대) 상태는 페이지를 벗어나거나 새로고침하면 저장되지 않고 초기 상태로 돌아가는 것으로 가정한다.
- **[amended]** 본문 인라인 마인드맵은 확대·축소·화면 이동(드래그/휠)을 지원하지 않는 것으로 가정을 변경한다 — Mermaid/PlantUML macOS 프리뷰와의 인터랙션 일관성, 그리고 인라인 팬/줌이 페이지 스크롤을 가로채는 문제(트랙패드 스크롤 중 커서가 마인드맵 위를 지날 때 페이지가 안 움직이는 회귀)가 실사용 중 확인되어, 확대/축소·이동은 확대 보기 창에서만 제공하기로 변경했다. 가지 접기/펼치기는 뷰 상태를 바꾸지 않아 이 문제와 무관하므로 인라인에 그대로 남긴다.
- 확대 보기 창과 복사 버튼의 위치·스타일은 기존 Mermaid/PlantUML 다이어그램 및 이미지 라이트박스 모달과 완전히 동일한 사용자 경험을 따르는 것으로 가정한다.
- 문법/구조 오류 시 대체 표시 방식은 이 프로젝트에 이미 있는 Mermaid/PlantUML 다이어그램의 오류 처리 관례(오류 위치에 원본 코드를 그대로 노출)를 따르는 것으로 가정한다.
- Markmap 외 다른 마인드맵/다이어그램 포맷(예: Mermaid의 mindmap 다이어그램 타입, jsMind, MindElixir)은 이번 범위에서 명시적으로 제외한다.
