# Feature Specification: Giscus 게시글 댓글

**Feature Branch**: `008-giscus-comments`

**Created**: 2026-07-21

**Status**: Draft

**Input**: User description: "게시글 세부 페이지(article detail page) 하단에 giscus 기반 GitHub 댓글 기능을 추가한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 로그인 없이 댓글 읽기 (Priority: P1)

방문자는 GitHub 계정이 없어도 게시글 세부 페이지 하단에서 기존에 달린 댓글과 반응을 읽을 수 있다.

**Why this priority**: 댓글 기능의 가장 기본적인 가치는 "읽기"다. 대부분의 방문자는 로그인하지 않은 상태로 글을 읽으므로, 로그인 여부와 무관하게 댓글이 보이지 않으면 기능 자체가 무의미해진다.

**Independent Test**: 로그인하지 않은 브라우저 세션으로 댓글이 하나 이상 달린 게시글에 접속해, 페이지 하단에서 기존 댓글 목록과 반응이 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로그인하지 않은 방문자가 댓글이 존재하는 게시글에 접속한 상태, **When** 페이지 하단까지 스크롤하면, **Then** 기존 댓글과 반응이 표시된다.
2. **Given** 로그인하지 않은 방문자가 아직 댓글이 없는 게시글에 접속한 상태, **When** 페이지 하단까지 스크롤하면, **Then** "아직 댓글이 없다"는 안내와 함께 로그인 유도 UI가 표시된다.

---

### User Story 2 - GitHub 계정으로 댓글 작성 (Priority: P2)

GitHub 계정을 가진 사용자는 게시글 세부 페이지 하단에서 GitHub 계정으로 로그인하여 댓글을 작성할 수 있다.

**Why this priority**: 읽기(P1)가 확보된 다음 단계로, 댓글 기능의 핵심 상호작용(작성)이 동작해야 실제로 "댓글 기능이 있다"고 말할 수 있다.

**Independent Test**: GitHub 계정으로 로그인한 브라우저 세션으로 게시글에 접속해, 댓글을 작성하고 목록에 반영되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** GitHub 계정으로 로그인하지 않은 사용자가 댓글 작성을 시도하는 상태, **When** 댓글 입력창을 클릭하면, **Then** GitHub 로그인 절차로 안내된다.
2. **Given** GitHub 계정으로 로그인한 사용자가 게시글에 접속한 상태, **When** 댓글을 입력하고 제출하면, **Then** 별도 새로고침 없이 댓글 목록에 자신의 댓글이 추가된다.

---

### User Story 3 - 사이트 테마와 댓글 위젯 테마 동기화 (Priority: P3)

사용자가 사이트 상단의 다크/라이트 테마 토글을 누르면, 이미 로드되어 있는 댓글 위젯의 테마도 즉시 함께 전환된다.

**Why this priority**: 필수 기능(읽기/쓰기)이 아니라 시각적 일관성에 관한 것이라 P1/P2보다 우선순위가 낮지만, 이 프로젝트는 다크/라이트 페어를 제품의 핵심으로 취급하므로 댓글 위젯만 테마가 어긋나면 완성도가 크게 떨어진다.

**Independent Test**: 댓글 위젯이 로드된 상태에서 사이트 테마 토글을 클릭해, 페이지 새로고침 없이 댓글 위젯의 배경/텍스트 색상이 사이트 테마와 일치하게 바뀌는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 라이트 테마에서 댓글 위젯이 이미 로드된 상태, **When** 사용자가 다크 테마로 전환하면, **Then** 댓글 위젯도 다크 테마로 즉시 바뀐다.
2. **Given** 다크 테마에서 댓글 위젯이 이미 로드된 상태, **When** 사용자가 라이트 테마로 전환하면, **Then** 댓글 위젯도 라이트 테마로 즉시 바뀐다.

---

### Edge Cases

- 댓글 위젯 로딩에 실패하면(네트워크 오류, 서드파티 스크립트 차단 등) 어떻게 되는가? → 게시글 본문/네비게이션 등 나머지 페이지 기능에는 영향을 주지 않아야 한다.
- 사용자가 댓글 영역까지 스크롤하지 않으면 댓글 스크립트를 아예 로드하지 않아야 한다(초기 페이지 성능 보호).
- 아직 어떤 댓글도 달리지 않은 게시글(새로 발행된 글)에서는 어떻게 보이는가? → 빈 상태 UI(로그인 유도 + "첫 댓글을 남겨보세요" 형태)가 노출된다.
- 사용자가 페이지 내 테마를 여러 번 빠르게 전환하는 경우에도 댓글 위젯이 깨지거나 재로드로 인해 깜빡이지 않아야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 게시글 세부 페이지의 이전/다음 글 네비게이션 아래, 페이지 최하단에 댓글 섹션을 노출해야 한다.
- **FR-002**: 시스템은 GitHub 계정이 없는 방문자도 기존 댓글과 반응을 읽을 수 있게 해야 한다.
- **FR-003**: 시스템은 GitHub 계정으로 로그인한 사용자가 댓글을 작성할 수 있게 해야 한다.
- **FR-004**: 댓글은 게시글의 고유 경로를 기준으로 매핑되어, 서로 다른 게시글의 댓글이 섞이지 않아야 한다.
- **FR-005**: 사용자가 사이트의 다크/라이트 테마를 전환하면, 이미 로드된 댓글 위젯도 페이지 새로고침이나 위젯 재마운트 없이 테마가 즉시 반영되어야 한다.
- **FR-006**: 댓글 위젯은 게시글 본문 및 최초 페이지 렌더링을 지연시키지 않아야 하며, 사용자가 댓글 영역 근처로 스크롤하기 전까지 로드되지 않아야 한다.
- **FR-007**: 다크/라이트 정적 디자인 목업 두 파일은 댓글 섹션의 레이아웃과 스타일을 동일하게 반영해야 하며, 하나만 갱신된 상태로 존재해서는 안 된다.
- **FR-008**: 댓글 섹션은 게시글 페이지에서 이미 쓰이고 있는 타이포그래피, 컬러, 아이콘 스타일과 시각적으로 일관되어야 한다.
- **FR-009**: 댓글의 저장과 모더레이션(스팸/악성 댓글 관리 등)은 외부 서비스(GitHub Discussions)에 위임하며, 이 기능은 위젯 임베드까지만 책임진다.

### Key Entities

- **댓글(Comment)**: 방문자가 게시글에 남기는 글. 작성자의 GitHub 아이덴티티, 본문, 작성 시각을 포함하며 저장/영속화는 외부 서비스가 담당한다.
- **반응(Reaction)**: 게시글 또는 댓글에 대한 이모지 형태의 짧은 피드백.
- **게시글-댓글 매핑**: 게시글의 고유 경로와 해당 게시글에 속한 댓글 묶음 간의 연결 관계.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 로그인하지 않은 방문자의 100%가 게시글 세부 페이지 하단에서 기존 댓글과 반응을 읽을 수 있다.
- **SC-002**: GitHub 계정으로 로그인한 사용자가 댓글을 작성하면, 페이지를 새로고침하지 않아도 1초 이내에 자신의 댓글이 목록에 반영된 것을 확인할 수 있다.
- **SC-003**: 사용자가 사이트 테마를 전환하면 1초 이내에 댓글 위젯의 테마도 사이트 테마와 일치한다.
- **SC-004**: 댓글 영역에 도달하기 전까지 댓글 관련 리소스가 로드되지 않아, 게시글 본문의 최초 표시 속도에 댓글 기능으로 인한 지연이 발생하지 않는다.
- **SC-005**: 다크/라이트 두 모드 모두에서 댓글 섹션의 디자인이 게시글 페이지의 다른 섹션과 동일한 톤을 유지한다(별도 이질감 없이 시각적으로 통합된 것으로 확인된다).

## Assumptions

- 댓글 데이터를 저장할 전용 public GitHub 저장소, 그 저장소의 Discussions 활성화, giscus GitHub App 설치는 이 기능의 선행 조건으로 이미 완료되어 있다고 가정한다.
- 방문자는 서드파티 스크립트나 iframe을 차단하지 않는 일반적인 브라우저 환경을 사용한다고 가정한다. 광고 차단기 등으로 위젯이 차단되는 경우는 외부 서비스 자체의 알려진 한계로 간주하고 이 기능 범위에서 별도로 대응하지 않는다.
- 댓글 작성자의 신원 확인과 스팸 관리 정책은 GitHub Discussions의 기본 정책을 그대로 따르며, 별도의 자체 모더레이션 도구는 이 기능 범위에 포함하지 않는다.
- 이 기능은 게시글 세부 페이지에만 적용되며, 다른 페이지(홈, 검색 결과 등)에는 댓글 기능을 추가하지 않는다.
