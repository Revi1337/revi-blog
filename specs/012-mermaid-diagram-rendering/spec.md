# Feature Specification: Mermaid 다이어그램 렌더링

**Feature Branch**: `012-mermaid-diagram-rendering`

**Created**: 2026-08-15

**Status**: Draft

**Input**: User description: "블로그 아티클 콘텐츠 파이프라인에 Mermaid 다이어그램을 아티클 본문에서 시각적으로 렌더링하는 기능을 추가한다. 현재는 ```mermaid 코드펜스를 써도 문법이 강조된 텍스트 코드 블록으로만 보일 뿐, 실제 순서도/시퀀스 다이어그램 같은 그림으로 표시되지 않는다. GitHub은 이미 이 문법을 코드블록에 적으면 자동으로 그림으로 렌더링해주는데, 이 블로그 독자에게도 동일한 경험을 제공해야 한다. 저자는 옵시디언 등에서 작성한 원고를 그대로 옮겨와도 다이어그램이 깨지지 않고 의도한 모습 그대로 나타나길 기대하고, 독자는 페이지 접속 즉시 완성된 그림을 볼 수 있어야 하며 그림을 보기 위해 별도의 클릭/조작이 필수여서는 안 된다. 다이어그램 문법에 오류가 있어도 페이지 전체 렌더링이 깨지면 안 되고, 다크/라이트 테마 전환 시에도 다이어그램이 읽기 가능한 상태를 유지해야 한다. 기존에 발행된 아티클들의 렌더링 결과는 이번 변경으로 달라지지 않아야 한다. 렌더링된 다이어그램에는 GitHub과 동일하게 복사 버튼과 확대 버튼 두 개가 함께 표시되어야 한다. 복사 버튼을 누르면 화면에 그려진 그림이 아니라 원본 Mermaid 코드 텍스트가 클립보드에 복사되어야 한다. 확대 버튼을 누르면, 이 블로그가 본문 이미지를 클릭했을 때 이미 보여주고 있는 라이트박스 모달과 동일한 방식의 확대 보기 창이 떠야 한다. 이 확대 보기 창에는 상하좌우로 그림을 이동시키는 화살표 버튼, 이동/확대 상태를 원래대로 되돌리는 새로고침(리셋) 버튼, 그림을 키우고 줄이는 돋보기 +/- 버튼이 반드시 포함되어야 한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 독자가 다이어그램을 그림으로 바로 본다 (Priority: P1)

독자가 Mermaid 문법(순서도, 시퀀스 다이어그램 등)이 포함된 아티클 페이지에 접속하면, 문법이 강조된 텍스트 코드 블록이 아니라 실제로 조판된 그림을 즉시 볼 수 있어야 한다. 그림을 보기 위해 클릭이나 별도 조작이 필요해서는 안 된다.

**Why this priority**: 이번 기능의 핵심 가치이며, 나머지(복사/확대) 기능은 이 렌더링이 존재해야 의미가 있다. 이것만으로도 GitHub과 동등한 열람 경험이라는 목표를 달성한다.

**Independent Test**: Mermaid 코드펜스만 포함된 아티클을 발행해, 페이지 로드 즉시 그림이 렌더링되는지 확인하는 것으로 독립 검증 가능.

**Acceptance Scenarios**:

1. **Given** 본문에 유효한 Mermaid 순서도 문법이 있는 아티클, **When** 페이지를 렌더링하면, **Then** 원본 코드 텍스트가 아니라 조판된 순서도 그림이 표시된다.
2. **Given** 다크 모드와 라이트 모드, **When** 동일한 다이어그램을 각각 렌더링하면, **Then** 두 테마 모두에서 다이어그램 요소와 배경이 읽기 충분한 명도 대비로 표시된다.
3. **Given** 이번 변경 이전에 발행된, Mermaid 문법을 쓰지 않는 기존 아티클, **When** 페이지를 렌더링하면, **Then** 기존과 동일한 결과가 나온다(회귀 없음).

---

### User Story 2 - 독자가 다이어그램을 확대해서 자세히 본다 (Priority: P2)

독자가 렌더링된 다이어그램의 확대 버튼을 누르면, 이 블로그가 본문 이미지를 클릭했을 때 보여주는 라이트박스와 동일한 방식의 확대 보기 창이 뜬다. 이 창에서 그림을 상하좌우로 이동시키고, 확대/축소하고, 조작을 원래 상태로 되돌릴 수 있어야 한다.

**Why this priority**: 다이어그램은 본문 폭에 맞춰 작게 그려질 수 있어, 복잡한 다이어그램일수록 세부 내용을 보기 위한 확대 열람이 독자 경험에 중요하다.

**Independent Test**: 렌더링된 다이어그램의 확대 버튼을 눌러 확대 보기 창이 뜨는지, 그 안에서 이동/리셋/확대·축소 조작이 각각 의도대로 동작하는지 확인하는 것으로 독립 검증 가능.

**Acceptance Scenarios**:

1. **Given** 렌더링된 다이어그램, **When** 확대 버튼을 클릭하면, **Then** 기존 이미지 라이트박스와 동일한 방식의 확대 보기 창이 뜬다.
2. **Given** 확대 보기 창이 열린 상태, **When** 상하좌우 화살표 버튼을 클릭하면, **Then** 그림이 해당 방향으로 이동한다.
3. **Given** 확대 보기 창에서 이동/확대를 조작한 상태, **When** 리셋 버튼을 클릭하면, **Then** 이동 위치와 확대 배율이 모두 최초 상태로 되돌아간다.
4. **Given** 확대 보기 창이 열린 상태, **When** 돋보기 +/- 버튼을 클릭하면, **Then** 그림이 각각 확대/축소된다.

---

### User Story 3 - 독자가 다이어그램의 원본 코드를 복사한다 (Priority: P3)

독자가 렌더링된 다이어그램의 복사 버튼을 누르면, 화면에 그려진 그림이 아니라 원본 Mermaid 코드 텍스트가 클립보드에 복사된다.

**Why this priority**: GitHub과 동일한 부가 기능이지만, 핵심 열람 경험(그림으로 보기)이나 세부 확인(확대 보기)에 비해 사용 빈도가 낮을 것으로 예상되는 보조 기능이다.

**Independent Test**: 복사 버튼을 클릭한 뒤 클립보드 내용이 원본 Mermaid 코드 텍스트와 정확히 일치하는지 확인하는 것으로 독립 검증 가능.

**Acceptance Scenarios**:

1. **Given** 렌더링된 다이어그램, **When** 복사 버튼을 클릭하면, **Then** 클립보드에는 렌더링 이미지가 아니라 원본 Mermaid 코드 텍스트가 담긴다.

---

### Edge Cases

- 다이어그램 문법에 오류(괄호 불일치 등)가 있으면 어떻게 되는가? → 페이지 전체 렌더링이 깨지지 않고, 오류가 발생한 자리에는 원본 코드가 그대로 표시된다.
- 다이어그램이 본문 폭보다 넓게 그려지면 어떻게 되는가? → 레이아웃이 깨지지 않고 본문 폭에 맞게 표시된다.
- 확대 보기 창에서 리셋 버튼을 누르면 어떻게 되는가? → 이동 위치와 확대 배율이 모두 최초 상태로 되돌아간다.
- 옵시디언 등 다른 저작 도구에서 작성한 원고를 그대로 옮겨온 경우는 어떻게 되는가? → 별도 수정 없이도 원고 작성자가 의도한 모습 그대로 렌더링된다.
- 이번 변경 이전에 발행된, Mermaid 문법을 쓰지 않는 아티클은 어떻게 되는가? → 기존 렌더링 결과가 달라지지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 ```mermaid 코드펜스를 문법 강조된 텍스트가 아니라 실제 다이어그램(순서도, 시퀀스 다이어그램 등)으로 렌더링해야 한다.
- **FR-002**: 독자는 페이지 접속 즉시, 별도의 클릭이나 조작 없이 완성된 다이어그램을 볼 수 있어야 한다.
- **FR-003**: 시스템은 렌더링된 다이어그램마다 복사 버튼과 확대 버튼을 함께 표시해야 한다.
- **FR-004**: 시스템은 복사 버튼 클릭 시 렌더링된 그림이 아니라 원본 Mermaid 코드 텍스트를 클립보드에 복사해야 한다.
- **FR-005**: 시스템은 확대 버튼 클릭 시 기존 이미지 라이트박스 모달과 동일한 방식의 확대 보기 창을 띄워야 한다.
- **FR-006**: 확대 보기 창은 상하좌우로 그림을 이동시키는 화살표 버튼을 제공해야 한다.
- **FR-007**: 확대 보기 창은 이동/확대 상태를 최초 상태로 되돌리는 리셋 버튼을 제공해야 한다.
- **FR-008**: 확대 보기 창은 그림을 확대/축소하는 돋보기 +/- 버튼을 제공해야 한다.
- **FR-009**: 시스템은 다이어그램 문법에 오류가 있어도 페이지 전체 렌더링이 실패하지 않아야 하며, 오류가 발생한 자리에는 원본 코드를 그대로 표시해야 한다.
- **FR-010**: 시스템은 다크 모드와 라이트 모드 각각에서 다이어그램이 읽기 충분한 명도 대비로 표시되도록 해야 한다.
- **FR-011**: 시스템은 이번 변경 이전에 발행된 아티클들의 렌더링 결과를 이번 변경으로 인해 달라지게 해서는 안 된다.
- **FR-012**: 시스템은 다이어그램이 본문 폭보다 넓은 경우에도 레이아웃이 깨지지 않도록 해야 한다.

### Key Entities

- **Mermaid 다이어그램 블록**: 본문 중 Mermaid 문법으로 작성된 하나의 다이어그램. 원본 코드, 렌더링된 그림, 문법 오류 여부를 속성으로 가진다.
- **확대 보기 창**: 다이어그램을 크게 보기 위한 모달. 이동 위치와 확대 배율을 상태로 가지며, 리셋 시 두 값 모두 초기 상태로 돌아간다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Mermaid 문법이 포함된 아티클에 접속하면 100%의 경우 별도 조작 없이 완성된 다이어그램을 즉시 볼 수 있다.
- **SC-002**: 복사 버튼 클릭 시 100%의 경우 클립보드 내용이 렌더링 이미지가 아니라 원본 다이어그램 코드와 정확히 일치한다.
- **SC-003**: 확대 보기 창의 이동/리셋/확대·축소 조작 각각이 100% 의도한 결과(위치 이동, 최초 상태 복구, 배율 변경)를 낸다.
- **SC-004**: 문법 오류가 있는 다이어그램이 포함된 페이지도 100% 정상적으로 로드되며, 페이지의 다른 콘텐츠 열람에 영향을 주지 않는다.
- **SC-005**: 다크/라이트 두 테마 각각에서 다이어그램이 시각적으로 구분 가능한 명도 대비를 유지한다.
- **SC-006**: 기존에 발행된 아티클들의 렌더링 결과가 이번 변경 적용 전후로 동일하다.

## Assumptions

- 지원 대상 다이어그램 문법은 표준 Mermaid 문법 범위로 가정하며, 실험적/비표준 확장 문법 지원은 이번 범위 밖으로 가정한다.
- 확대 보기 창의 조작 방식(패닝 화살표, 리셋, 확대/축소 +/-)은 기존 이미지 라이트박스 모달과 동일한 사용자 경험을 따르는 것으로 가정한다.
- 문법 오류 시 대체 표시 방식은 이 프로젝트에 이미 있는 수식 렌더링의 오류 처리 관례(오류 위치에 원본 텍스트를 그대로 노출)를 따르는 것으로 가정한다.
- Mermaid 외 다른 다이어그램/마인드맵/드로잉 포맷(예: Markmap, Excalidraw)은 이번 범위에서 명시적으로 제외한다.
